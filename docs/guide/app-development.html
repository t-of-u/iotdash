เขียนแอปสำหรับ iotdash

แอปคือโปรเจกต์ HTML/CSS/JS ธรรมดา อยู่ที่ไหนก็ได้ (ไม่ต้องอยู่ใน SDK) ที่เปิดใน Chromium ได้ตามปกติ เครื่องมือ build จะวัดหน้าใน Chromium แล้ว compile เป็น image เดียว (app.idb) พร้อม font และรูปที่แปลงแล้ว หน้านี้อธิบายโครงสร้าง, API ที่ใช้บ่อย, วิธีติดตั้ง และเทคนิคให้แอปเร็วและประหยัดหน่วยความจำบนบอร์ด โดยใช้ Calculator (examples/calculator ใน SDK) เป็นตัวอย่าง แอปเป็นของผู้เขียน: SDK ไม่ได้รวมแอปไว้ และ store ก็แค่เก็บแพ็กเกจ

เริ่มเร็ว

iotdash create hello             # โฟลเดอร์ hello/ จาก template (iotdash ต้องอยู่ใน PATH: ดู ติดตั้ง)
cd hello
iotdash run                      # build + ลง simulator + เปิดแอป
iotdash run --device             # ลงบอร์ดผ่าน USB + เปิดแอป

หรือเขียนเองทั้งหมด: ขั้นต่ำคือ app.json กับ main.html

{ "id": "hello", "title": "Hello", "version": "1.0" }      ← app.json

<!doctype html>                                           ← main.html
<html><head><meta charset="utf-8">
<link rel="stylesheet" href="/system/theme.css">
</head><body>
  <h1 id="t">สวัสดี</h1>
  <script>
    document.getElementById('t').addEventListener('click', () => os.alert('Hello', 'tapped'));
  </script>
</body></html>

Path ที่หน้าเห็น

Pathชี้ไปที่
/system/theme.csstheme ของระบบ (สี, dark mode) ใช้ร่วมได้ทุกแอป
relative เช่น lib/calc.css, ../../lib/calc.jsไฟล์ในแอปเดียวกัน (resolve จากหน้าปัจจุบัน)
fetch('data.json')ไฟล์ใน image (อ่านอย่างเดียว)
open('x.txt'), fs.readFile('x')/applications/<id>/data/x บน storage (อ่านเขียนได้)

หน้าและการนำทาง

  • หน้าแรกคือ main.html หน้าอื่นต้องอยู่ใต้ pages/
  • navigate('history/main.html') เปิดหน้าใหม่ (slide ไปซ้าย) navigate(-1) หรือ history.back() ย้อนกลับ
  • <a href="pages/x/main.html"> ก็ใช้ได้ (ผ่าน navigation stack เหมือนกัน) <a href="#back"> หรือ data-back ย้อนกลับ
  • ทุกหน้าเริ่มด้วย JS ใหม่ทั้งหมด ข้อมูลที่ต้องส่งข้ามหน้าเก็บใน localStorage, ไฟล์ หรือ APP process (+ os.emit)
  • การย้อนกลับเปิดหน้านั้นใหม่ (ไม่ได้คืน DOM เดิม): หน้าที่ย้อนกลับมาต้องอ่านสถานะจาก storage ตอนเริ่ม
  • ปุ่ม back ของระบบบนหน้าแรกจะถามว่าจะปิดแอปไหม

เก็บข้อมูล

ต้องการใช้ตัวอย่างใน Calculator
สถานะเล็กๆ ที่อยู่ข้ามหน้าและข้ามการเปิดแอปlocalStorageexpr, ans, count
ข้อมูลยาว, log, ไฟล์ binaryopen(path, mode), fs.*history.txt (append ทีละบรรทัด), stats.json
ค่าตั้งของระบบregistry.get('darkMode'), os.theme()–
สถานะชั่วคราวในหน้าเดียวตัวแปร JS หรือ sessionStorage–
// ต่อท้ายไฟล์ทีละบรรทัด
const f = open('history.txt', 'a');
f.writeLine(`${expression} = ${result}`);
f.close();

// อ่านทั้งไฟล์ / JSON
const lines = fs.exists('history.txt') ? open('history.txt', 'r').readLines() : [];
fs.writeJSON('stats.json', {count, updated: Date.now()});

ค่าใน localStorage อยู่ถาวร: ถ้าเก็บสิ่งที่อยู่บนจอไว้ (เช่นตัวเลขที่กำลังพิมพ์) เมื่อปิดแล้วเปิดแอปใหม่จะเห็นค่าเดิม ถ้าต้องการให้เริ่มใหม่ทุกครั้งที่เปิด ให้เก็บใน APP process หรือรอ sessionStorage ระดับแอป (ดู ข้อจำกัด)

งานเบื้องหลัง

// ทำงานต่อแม้เปลี่ยนหน้า จนกว่าจะออกจากแอป
setBackgroundProcess('stats', 'APP', () => {
  const count = +localStorage.getItem('count') || 0;
  let saved = -1;
  try { saved = fs.readJSON('stats.json').count; } catch (_) {}
  if (saved !== count) fs.writeJSON('stats.json', {count, updated: Date.now()});
}, 2000);

// เฉพาะหน้านี้ (เช่นนาฬิกาบน home)
setBackgroundProcess('clock', 'PAGE', tick, 1000);
  • งานทั้งหมดของแอป (timer + process) ได้งบ 10 ms ต่อ tick ส่วนที่เกินรอ tick ถัดไป
  • callback ที่รันเกิน 3 วินาทีถูกหยุด process/interval นั้นถูกปิดถาวร
  • process แบบ APP ที่สร้างในหน้าหนึ่งจะทำให้ JS realm ของหน้านั้นค้างในหน่วยความจำ (~400 KB) สร้าง APP process เฉพาะเมื่อจำเป็น และอย่าให้ closure ถืออ้างอิง DOM ของหน้า

รายการ API ทั้งหมดอยู่ใน JavaScript API ของ OS

อินเทอร์เน็ตและ Bluetooth

  • แอปไม่ได้เปลี่ยนการเชื่อมต่อเอง (สวิตช์, เลือกเครือข่าย, รหัส เป็นของ Settings) แต่อ่านสถานะได้: os.net.online(), os.net.on(fn), os.wifi.state() ถ้าแอปใช้งานไม่ได้เมื่อไม่มีเน็ต ให้บอกผู้ใช้พร้อมปุ่ม os.launch('settings') (เช่น popup ที่บังหน้าจอจนกว่าอินเทอร์เน็ตจะกลับมา)
  • อุปกรณ์ BLE ใช้ได้เต็มที่: os.bt.scan(), connect(), subscribe(), write() Bluetooth เปิดเองเมื่อเรียกครั้งแรก อุปกรณ์ที่ต่อสำเร็จถูกจำไว้ (os.bt.devices()) ต้องรับมือ event disconnected และต่อใหม่เอง
  • Date เป็นเวลาจริงหลัง Wi-Fi ต่อครั้งแรกเท่านั้น (NTP) และ Function.prototype.toString() ไม่คืน source (ดู ข้อต่างจาก browser)

Theme และ dark mode

link /system/theme.css แล้วใช้ตัวแปร:

ตัวแปรใช้กับ
--bg, --surface, --surface-2พื้นหลังหน้า, การ์ด, พื้นรอง
--text, --muted, --lineข้อความ, ข้อความรอง, เส้นแบ่ง

dark mode ของระบบ (registry darkMode) ทำให้ @media (prefers-color-scheme: dark) เป็นจริงในทุกหน้า theme.css กำหนดค่าตัวแปรชุดมืดไว้แล้ว ถ้ามีสีของแอปเองให้เพิ่ม media query แบบเดียวกัน (เหมือน .key.op ใน Calculator)

Font

  • family ที่มี: Inter (ค่าเริ่มต้นของ sans-serif ทุกชื่อ), Noto Sans Thai, JetBrains Mono (monospace) ไทยใช้ Noto Sans Thai เป็น fallback อัตโนมัติ
  • ทุก (family, weight, size) ที่หน้าใช้จะกลายเป็น atlas หนึ่งไฟล์ในแอป ยกเว้นขนาดที่ system image มีอยู่แล้ว (แอปใช้ร่วมกับระบบ ไม่ต้องพกเอง)

ขนาดที่ system มีในตอนนี้ (จาก os/build/system-fonts.json, เปลี่ยนได้เมื่อหน้าของระบบเปลี่ยน):

เลือกขนาดจากตารางนี้เมื่อทำได้: image เล็กลง, โหลดเร็วขึ้น และไม่มี atlas เพิ่มในแอป (font ทุกขนาดถูกโหลดเข้า RAM ใหม่ต่อ document และกิน ≈26 KB ต่อ face ไม่ว่าจะเป็นของระบบหรือของแอป ดู หน่วยความจำ) ขนาดที่ใหญ่กว่า 34 px ได้เฉพาะตัวอักษรที่หน้าใช้จริงที่ขนาดนั้น ถ้า JS สร้างข้อความใหม่ที่ขนาดใหญ่ (เช่นตัวอักษรที่ไม่เคยอยู่ในไฟล์) ตัวนั้นจะไม่แสดง ใส่ตัวอย่างข้อความไว้ใน HTML (เช่น element ที่ display: none) เพื่อให้ build รู้

ประหยัดหน่วยความจำ

บทเรียนจากแอปตาชั่งขนาดใหญ่ที่เคยทำให้ PSRAM เหลือ 15 KB (ฝั่ง engine แก้ไปแล้ว ดู หน่วยความจำและ storage):

ทำเพราะ
ส่งรูปที่ขนาดแสดงจริงbuild เก็บรูปได้ถึง 2 เท่าของขนาดใหญ่สุดที่หน้าแสดง แล้วรูปถูก decode เป็น RGB565 + alpha (3 byte ต่อ pixel) ใน RAM: โลโก้ที่แสดง 84 px แต่ส่งไฟล์ 276 px กลายเป็น 168 px = 85 KB ใน RAM ส่งที่ 84 px เหลือ 21 KB
ใช้ขนาด font ของระบบทุก (weight, size) ที่หน้าใช้กินตาราง ≈26 KB (ไทย ≈14 KB) ตลอดเวลาที่หน้านั้นเปิด + bitmap ของ glyph ขนาดของระบบดูใน ตารางด้านบน (Inter 400: 13/14/15/16/18/20/21/24/40, 500: 15/16, 600: 13/15/16/18/20/24/30/44, 700: 16)
ประกาศขนาดตัวอักษรที่ script สร้างทีหลังไว้ใน element ที่ซ่อนbuild อ่าน font ของทุก element รวมที่ display: none แต่บอร์ดไม่ต้อง layout มัน เช่น <div id="kit"><div class="big-num">- 0123456789.,</div></div> + #kit { display: none } ทำให้ตัวเลข 64 px ที่ JS สร้างทีหลังมี glyph (ใช้กับรูปไม่ได้: build ไม่วัดขนาดรูปที่ซ่อนอยู่)
ลบ listener และ reference ของจอเก่าเมื่อสร้างจอใหม่ด้วย innerHTMLwrapper ที่ติด cycle รอ GC (ระบบเรียก GC เองหลังเปลี่ยนจอ ≈35 ms) element ที่ถูกถอดไม่ถือ computed style แล้ว แต่ยังถือ DOM และข้อมูล layout
ดูตัวเลขระหว่างพัฒนาmem [tag] ใน script ของ sim ทุกหน้าจอ, psram ใน stats บนบอร์ด และเดินจอเดิมซ้ำหลายรอบดูว่าคงที่

ทำเพราะ

วงจรพัฒนา

  1. แก้ไฟล์ แล้ว iotdash run (simulator) หรือ iotdash run --web (เบราว์เซอร์)
  2. เทียบกับ Chromium: iotdash shot (--page pages/x/main.html, --dark) ได้ build/compare.png (ซ้าย simulator, ขวา Chromium ที่มี stub ของ os, fs, registry และ font ของระบบ)
  3. ลงบอร์ด: iotdash run --device (ข้อมูลเดิมของแอปยังอยู่; ถ้าแอปเปิดอยู่จะปิดก่อนแล้วเปิดใหม่)
  4. ถ่ายจอจริง: iotdash device shot out.png, ดูตัวเลข: iotdash device stats
  5. ปล่อยเวอร์ชัน: เพิ่ม version แล้ว iotdash pack (ลองแพ็กเกจจริง: iotdash install --pack build/<id>-<ver>.idbz) แล้วอัปโหลดในเว็บของ store หรือ iotdash publish --store URL
  6. ถอนการติดตั้ง: iotdash uninstall [--to device] (ลบ memory.json และ data/ ด้วย)

คำสั่งทั้งหมดอยู่ใน เครื่องมือ command line

ตัวอย่างทั้งแอป: Calculator

  • main.html: แถบบน (ชื่อ + chip History/Scientific), ช่องแสดงผลสูง 104 px, grid ปุ่ม 4 × 5 ปุ่มใช้ data-k และ listener ตัวเดียวบน #keys (event delegation)
  • lib/calc.js: Calc.evaluate(expr, {ans}), Calc.format, saveHistory (append ลง history.txt), readHistory ใช้ร่วมกันทุกหน้า
  • สถานะ: expr และ ans ใน localStorage ทุกหน้าจึงเห็นค่าเดียวกัน
  • pages/scientific: ปุ่มฟังก์ชัน (sin, cos, log, …) ใช้ Calc ตัวเดียวกัน
  • pages/history: อ่าน history.txt แสดงเป็นรายการ scroll ได้ ปุ่ม Clear ถามด้วย os.confirm
  • APP process stats: เขียน data/stats.json ทุก 2 วินาทีเมื่อจำนวนการคำนวณเปลี่ยน แม้อยู่หน้าอื่น
