Dev link และคำสั่งบนบอร์ด

ช่องทางเดียวระหว่างคอมพิวเตอร์กับบอร์ด: UART0 ผ่านชิป USB-serial ที่ 921600 baud มีทั้ง frame แบบ binary (ติดตั้งแอป, ถ่ายจอ, eval) และบรรทัดข้อความ (log และคำสั่ง debug) ปนกันในสายเดียว โค้ด: src/devlink.h/.cpp, onLink() ใน src/main.cpp, class Link ใน tools/iotdash.py

Frame

0xA5 0x5A  type:u8  len:u32le  payload[len]  crc32(payload):u32le
  • บอร์ดอ่านด้วย state machine (MAGIC1 → MAGIC2 → TYPE → LEN → PAYLOAD → CRC) frame ที่ CRC ผิดถูกทิ้ง
  • byte ที่ไม่ได้อยู่ใน frame และเป็น ASCII ที่พิมพ์ได้ ถูกสะสมเป็นบรรทัด เมื่อเจอ \n จะส่งเป็นคำสั่ง text (R_TEXT) สูงสุด 256 ตัวอักษร
  • ทางบอร์ด → คอมพิวเตอร์: frame ตอบกลับ + บรรทัด log ธรรมดา (devlink.log() thread-safe ด้วย TX lock)
  • log ของ ESP-IDF (ESP_LOGx) ถูก redirect ผ่าน esp_log_set_vprintf เข้า devlink.log ไม่ให้แทรกกลาง frame (เคยทำให้ภาพหน้าจอเสีย) log จาก task ที่ถือ TX lock อยู่จะถูกทิ้ง (กัน deadlock)
  • frame ขนาดใหญ่ (ภาพหน้าจอ) ส่งแบบ stream: begin(type, len) → write() หลายครั้ง → end() โดยคำนวณ CRC ระหว่างทาง ไม่ต้องมี buffer ทั้งก้อน

การเปิดพอร์ตจะ reset บอร์ด (สาย DTR/RTS) ทุกคำสั่งของ iotdash.py จึงรอ PING ก่อน และงานหลายขั้นควรทำใน connection เดียว

คำสั่ง text

ส่งเป็นบรรทัดข้อความ (เช่น printf 's\n' > /dev/cu.usbmodem… ไม่ได้เพราะจะ reset บอร์ด ให้ใช้ tools/devcmd.py หรือ pio device monitor)

~/.platformio/penv/bin/python tools/devcmd.py z sleep2 s     # reset stats, รอ 2 วินาที, พิมพ์ stats
tools/.venv/bin/python tools/devcmd.py ilog sleep10            # เปิด input log แล้วดู 10 วินาที

SD card และ probe (ฮาร์ดแวร์)

คำสั่งทำอะไร
sdส่ง CMD0 แบบดิบทั้งตอนไม่เลือกและเลือกการ์ด แล้วพิมพ์ byte ที่ได้ + ระดับ pull-up ของแต่ละสาย
probe / probe on / probe offstream แรงดันที่ GPIO6 (~10 บรรทัด/วินาที)
cs0 / cs1ค้าง CS ของการ์ดไว้ที่ low/high (หยุดการลอง mount)
sck0|sck1|sckz, mosi0|1|z, miso0|1|zขับสายนั้นเป็น 0/1 หรือปล่อยลอย (เห็น pull-up) ปล่อย SPI bus จนกว่าจะ sdauto
csauto / sdautoคืนทุกสายเป็นปกติ และกลับมาลอง mount
