Format ไฟล์และ layout

format แบบ binary ทั้งหมดที่เครื่องมือสร้างและบอร์ดอ่าน: image ของแอป/ระบบ (IDB1), แพ็กเกจแอปของ store (IDBZ), font atlas (FNT1), รูป (IMG1), header ของ flash slot (ISL1) และไฟล์ JSON บน storage ทุกตัวเลขเป็น little-endian

IDB1: image ของแอปและระบบ

archive แบบแบน ไฟล์ os.idb, app.idb, boot.idb สร้างโดย pack_bundle() (tools/iotdash.py) อ่านโดย Bundle (lib/rt/bundle.cpp)

"IDB1"            4 byte
count             u32
count × entry:    pathLen:u16  path[pathLen] (utf-8)  offset:u32  size:u32
padding           ให้ data แรกเริ่มที่ขอบ 4 byte
data              แต่ละไฟล์เริ่มที่ขอบ 4 byte (เรียงตามชื่อ)
  • offset นับจากต้น archive
  • บอร์ดอ่าน index ผ่าน ImageSource::read() แล้วเก็บเป็น ImageSlice ต่อไฟล์ (ไม่ map)
  • ถูก mount ที่ prefix: boot/, system/, app/ ไฟล์ main.html ในแอปจึงเป็น app/main.html

ไฟล์ที่ build ใส่ให้

Pathเนื้อหา
manifest.json{"entry": "main.html", "fonts": [{"file", "family", "weight", "size"}, …], "aliases": {...}, "built": unix}
fonts/<Family>-<weight>-<size>.fntatlas FNT1 (ขนาดทศนิยมใช้ _ เช่น Inter-400-15_5.fnt)
thai.dictคำไทยบรรทัดละคำ (จาก segmenter ของ Chromium) ใช้ตัดบรรทัด
รูปทุกไฟล์แปลงเป็น IMG1 แต่ยังใช้ชื่อเดิม (เช่น icon.svg เป็น IMG1 ภายใน)
assets/default-icon.img, apps/<id>/icon.img(system image) icon ขนาด 92 px

IDBZ: แพ็กเกจแอปของ store

ไฟล์ .idbz หนึ่งไฟล์คือแอปหนึ่งเวอร์ชัน (app.json, icon.img, app.idb) ต่อกันโดยไม่บีบอัด บอร์ดเขียนแต่ละไฟล์ลงการ์ดได้ทันทีระหว่างดาวน์โหลด ไม่ต้องแตกไฟล์และไม่ต้องมี RAM เท่าแพ็กเกจ สร้างโดย tools/idbz.py (iotdash pack) อ่านโดย IdbzWriter (lib/rt/os_store.cpp), backend ของ iotstore และ parseIdbz ใน web/iotdash-web.js

header 64 byte:   "IDBZ"  format:u16 (=1)  count:u16  manifestOffset:u32  manifestSize:u32
                  totalSize:u32  manifestSha256[32]  reserved[12]
count × entry 64: name[24] (utf-8, ปิดด้วย 0, ≤ 23 ตัว: A–Z a–z 0–9 . _ -)  offset:u32  size:u32  sha256[32]
manifest:         JSON {id, title, version, description, os: {built, min}, built}
files:            เรียงตาม offset แต่ละไฟล์เริ่มที่ขอบ 16 byte
  • ต้องมี app.json, icon.img, app.idb ครบ; manifest.id = ชื่อโฟลเดอร์บนการ์ด
  • ตอนติดตั้ง ทุกไฟล์ถูกเขียนลง /applications/.store-<id>/ พร้อมคำนวณ SHA-256 ถ้าตรงครบจึงย้ายแทนไฟล์ของแอป (app.idb ย้ายเป็นไฟล์สุดท้าย) memory.json และ data/ อยู่เหมือนเดิม
  • python3 tools/idbz.py FILE แสดง manifest, ไฟล์ และตรวจ checksum

FNT1: font atlas

glyph ที่ rasterize แล้ว (A8, gamma 0.72) ของหนึ่ง (family, weight, size) สร้างโดย build_atlas() อ่านโดย FontFace (lib/rt/font.h)

Header (112 byte)

FieldTypeความหมาย
magicchar[4]"FNT1"
version, flagsu16, u161, 0
size, ascent, descent, lineGap, xHeight, capHeight, underlinePos, underlineThickf32 × 8metric ของ face หลัก (px)
fbAscent, fbDescentf32 × 2metric ของ fallback (ไทย) ที่รวมไว้
glyphCount, kernCount, thaiCountu32 × 3จำนวนแถวของแต่ละตาราง
glyphOff, kernOff, thaiOff, bitmapOffu32 × 4offset ของตาราง/บล็อก bitmap
weightu16100–900
italic, reservedu8, u8
familychar[32]ชื่อ family

ตาราง

ตารางขนาดแถวField
Glyph (เรียงตาม cp)20 bytecp:u32 (≥ 0x110000 = variant ตามบริบท), adv64:i16 (1/64 px), bx, by:i16 (ซ้าย/บนเทียบ pen กับ baseline), w, h:u16, flags:u16 (1 fallback, 2 mark, 4 color), off:u32 (ในบล็อก bitmap)
Kerning (เรียงตาม pair)8 bytepair:u32 = (a << 16) | b (BMP เท่านั้น), adj64:i16, pad
Thai placement12 bytebase:u16, mark:u16 (+ bit บริบท: 0x8000 วรรณยุกต์บนสระบน, 0x4000 ตามด้วยสระอำ, 0xFFFF = base variant เช่น ญ ฐ ไม่มีหาง), glyph:u32 (0 = ตัว mark เอง), dx64, dy64:i16 (y ขึ้น)
Bitmap–A8 ต่อ glyph เรียงตามลำดับ glyph (ขนาดของ glyph i = off[i+1] − off[i]) บอร์ดคัดลอกทีละ glyph เข้า PSRAM

ถ้า base ที่ต้องการไม่มีในตาราง Thai จะใช้แถวของ ก (U+0E01) แทน; ASCII และช่วงไทย U+0E00–0E7F มีตาราง index ตรง ตัวอื่นใช้ binary search

IMG1: รูป

"IMG1"  w:u16  h:u16  format:u16  reserved:u16      (12 byte)
format 0: RGB565[w*h]                   ทึบ
format 1: RGB565[w*h] แล้วตามด้วย A8[w*h]   มี alpha
format 2: A8[w*h]                        mask (SVG ขาวดำ: เปลี่ยนสีด้วย CSS ได้)

สีถูก dither แบบ ordered 4×4 (Bayer) ก่อนตัดเป็น 565 เพื่อลดแถบสีใน gradient รูปถูกย่อตอน build ให้ด้านยาวไม่เกิน 2 เท่าของขนาดใหญ่สุดที่หน้าแสดงใน Chromium

ISL1: header ของ flash slot

partition sys (slot เดียว) และ slots (3 × 1.5 MB) แต่ละ slot เริ่มด้วย sector header 4 KB แล้วตามด้วย image

FieldTypeความหมาย
magicchar[4]"ISL1"
sizeu32ขนาด image
stampu32ลำดับการคัดลอก (slot ที่ stamp น้อยสุดถูกใช้ซ้ำก่อน)
keychar[48]"system" หรือ "app:<id>"
hashchar[24]hash จาก os.json/app.json (sha1 16 ตัวแรกของ image)

ลำดับการเขียน: ลบ header ก่อน → เขียน image ทีละ 64 KB → เขียน header สุดท้าย การคัดลอกที่ไม่จบจึงไม่มี magic และถูกคัดลอกใหม่ครั้งหน้า
