Simulator

sim/main.cpp compile engine ชุดเดียวกับบอร์ด (lib/rt + QuickJS) สำหรับ macOS/Linux จำลองจอ 800×480 RGB565, page buffer และการวาดเป็น band แบบเดียวกับบอร์ด รันได้ทั้งแบบหน้าต่าง (SDL2) และแบบ script (headless) ที่ถ่ายภาพได้ ใช้ทดสอบ OS, แอป และตรวจความถูกต้องของ engine ด้วย sanitizer

Build

# ปกติ: iotdash.py build ให้อัตโนมัติ (Release, sim/build)
cmake -S sim -B sim/build -DCMAKE_BUILD_TYPE=Release && cmake --build sim/build -j 8

# AddressSanitizer
cmake -S sim -B sim/build-asan -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="-fsanitize=address -fno-omit-frame-pointer"
cmake --build sim/build-asan -j 8

# ThreadSanitizer (ตรวจการวาดสองคอร์)
cmake -S sim -B sim/build-tsan -DCMAKE_CXX_FLAGS="-fsanitize=thread" && cmake --build sim/build-tsan -j 8
IOTDASH_SPLIT=1 sim/build-tsan/iotdash-sim …

ต้องมี ZLIB; SDL2 ไม่บังคับ (ไม่มีก็ใช้ได้เฉพาะ --shot/--script) build ที่มี sanitizer ใช้ stack ของ JS มากกว่า ให้ตั้ง RT_JS_STACK=256 (KB)

การรัน

# OS ทั้งระบบ (card ของ sim + boot image)
iotdash os sim --script "launch calculator; wait 300; shot calc.png"
sim/build/iotdash-sim --os os/build/sdcard --boot os/build/boot.idb [--script "…"] [--shot out.png]

# แอปเดี่ยว (ไม่มี OS)
sim/build/iotdash-sim APP/build/bundle.bin [--page x.html] [--script "…"] [--shot out.png]
  • มี --script หรือ --shot = headless: รัน script แล้วจบ (ถ้า script ไม่มี shot จะถ่าย --shot ให้ตอนท้าย)
  • ไม่มี = เปิดหน้าต่าง: เมาส์ = นิ้ว, ล้อเมาส์ = scroll, พิมพ์ได้ (Backspace, Enter, ลูกศร, Esc), F2 บันทึก sim-shot.png, F5/⌘R reload, โหมดแอปเดี่ยว reload เองเมื่อ bundle เปลี่ยน
  • เวลาใน script เป็น เวลาเสมือน: wait 300 เดิน engine ไป 300 ms ทันทีทีละเฟรม (39 Hz) ผลจึงเหมือนเดิมทุกครั้ง (ยกเว้น watchdog ของ JS ที่ใช้นาฬิกาจริง)
  • slide ระหว่างหน้าในหน้าต่างถูกจำลองแบบเดียวกับ compositor ของบอร์ด

คำสั่งใน script

คั่นคำสั่งด้วย ; หรือขึ้นบรรทัดใหม่ ก่อนคำสั่งแรกจะรัน 400 ms ให้หน้าโหลดเสร็จ

คำสั่งทำอะไร
wait MSเดินเวลาเสมือน
sleep MSรอเวลาจริง (ให้ process อื่นแก้ card ระหว่างนั้น เช่นทดสอบ install ขณะรัน)
tap X YDOWN แล้ว UP หลัง 60 ms
tapel SELECTORแตะกลาง element แรกที่ตรง selector (รวม overlay ภายในเช่นคีย์บอร์ด)
dragel SELECTOR DXลาก element ไปทางแนวนอน DX px ใน 12 ขั้น
down X Y, move X Y, up X Ypointer ทีละ event (+16 ms)
drag X1 Y1 X2 Y2 [MS=300]ลากแบบเส้นตรง
swipeupปัดขึ้นจากขอบล่าง (เปิดแถบระบบ)
type TEXT, key NAMEพิมพ์ข้อความ / กดปุ่ม (Backspace, Enter, …) ใน input ที่ focus
eval JSรัน JS แล้วพิมพ์ผล eval> …
shot FILE.pngบันทึก front buffer
open URLเปิดหน้าใน bundle โดยตรง
launch ID, home, backเทียบเท่าการกระทำของ OS (+400 ms)
regset KEY JSONตั้ง registry (เช่น regset darkMode true)
appschanged IDจำลอง frame APPS_CHANGED
rebootOs::reloadSystem()
ospageพิมพ์แอป/หน้า/ความลึกของ stack ปัจจุบัน
statsfps, เวลา style/layout/paint/frame, damage
bench [N=30]วาดใหม่ทั้งจอ N ครั้ง พิมพ์ ms ต่อครั้ง
relayout [N=30]layout ทั้งหน้า N ครั้ง
profครั้งแรกเริ่มเก็บ profile, ครั้งที่สองพิมพ์และ reset
micro, cliptestmicro-benchmark ของ raster, ทดสอบ clipping
dbg Nตั้ง rt::gDebugFlags แล้ววาดใหม่ทั้งจอ (เช่น dbg 16 = input log)
split 0|1|2วาด band แบบ 1 thread / 2 thread (เหมือนบอร์ด) / แบ่งครึ่งใน thread เดียว (ตรวจว่าการตัดซ้ายขวาไม่เปลี่ยนภาพ)
spincheckเรียก update() โดยไม่เดินเวลา ต้องหยุดวาดเอง (ไม่งั้นบอร์ดจะ spin ไม่ได้พัก)
layoutcheckพิมพ์จำนวน partial layout ที่ตรวจแล้ว/ไม่ตรง (ต้องรันด้วย RT_CHECK_LAYOUT=1)
mem [tag](macOS) heap ที่ใช้อยู่ทั้งหมด (ใกล้เคียงสิ่งที่ PSRAM ถือบนบอร์ด), JS heap, font ใน RAM และสำเนา resident: mem<tag>: N KB in use (js N KB, fonts N KB, resident N KB)
scale KG, scale OLวางน้ำหนักบนตาชั่ง BLE ปลอม / เกินพิกัด
scaleoffตาชั่งปลอมหลุดการเชื่อมต่อ

  tapel #toScientific; wait 400; ospage

Environment variable

ตัวแปรผล
IOTDASH_BUFFERS=2|3จำนวน page buffer (ค่าเริ่มต้น 2 เหมือนบอร์ด)
IOTDASH_SPLIT=0|1|2โหมดวาด band (เหมือนคำสั่ง split)
IOTDASH_BAND_ROWS=Nบังคับความสูงของ band (ค่าเริ่มต้นเหมือนบอร์ด: 16 KB ต่อ band, สูงสุด 64 แถว) ใช้ตรวจ culling
IOTDASH_DAMAGECHECK=1ทุกเฟรมที่ present ถูกเทียบกับการวาดใหม่ทั้งจอ ถ้าต่างจะพิมพ์ damagecheck: … px differ in x,y wxh และบันทึก /tmp/damage_N_shown.png/_ref.png (6 ครั้งแรก) พื้นที่ที่ไม่ถูกวาดเป็นสีม่วงแดง
IOTDASH_SLOWMEM=1image ถูกอ่านผ่าน read() แทนการใช้ในที่ (เหมือน flash slot ของบอร์ด) ทดสอบเส้นทางคัดลอก font/รูป
RT_JS_STACK=KBstack สูงสุดของ QuickJS (ค่าเริ่มต้น 32)
RT_CHECK_LAYOUT=1ทุก partial layout ถูกเทียบกับ full layout
RT_STYLE_DEBUG=1พิมพ์ขนาดของ rule index และค่า flag sibling/state-on-ancestors
RT_DAMAGE_DEBUG=1พิมพ์สี่เหลี่ยมที่วาดแต่ละเฟรมและ buffer ที่ present
RT_WANT_DEBUG=1พิมพ์เหตุผลที่ engine ต้องวาดเฟรม (style/layout/paint/js/…) ใช้หาสาเหตุที่ไม่ยอมหยุดวาด
RT_DUMP_LAYOUT=1dump กล่อง layout

Wi-Fi และ Bluetooth ปลอม

sim/fake_radio.h แทน radio ของบอร์ด: เครือข่ายปลอม 5 เครือข่าย (เช่น Home-WiFi / home1234, Cafe Free WiFi ไม่มีรหัส) และอุปกรณ์ BLE ปลอม 4 ตัว รวมตาชั่ง BLE-Scale-01 ที่ส่ง ST,GS,+0012.34kg\r\n 4 ครั้งต่อวินาที การตรวจอินเทอร์เน็ตและ fetch ภายนอกไปจริงผ่าน curl รายการทั้งหมดอยู่ที่ Wi-Fi และ Bluetooth

ในเบราว์เซอร์ (WebAssembly)

web/build.sh compile engine + OS ด้วย Emscripten (SDK ใน ~/emsdk) ได้ web/dist/: iotdash.js + iotdash.wasm (~2 MB), iotdash-web.js (driver) และ system image เว็บ iotstore ใช้ตัวนี้ในหน้า Simulate (npm run engine คัดลอกไป frontend/public/iotdash) ทดสอบเร็วๆ: cd web/dist && python3 -m http.server แล้วเปิด demo.html?pkg=<url ของ .idbz>

import { IotdashSim } from './iotdash-web.js';
const sim = new IotdashSim({ canvas, base: '/iotdash/', onLog, onRadio, onTare });
await sim.init();
const app = sim.installPackage(await (await fetch(url)).arrayBuffer());   // IDBZ
sim.boot(); sim.launch(app.id);
sim.setInternet(false); sim.setWifiReach(true); sim.scalePower(true);
sim.scale({ kg: 1.25, stable: true });      // สิ่งที่ตาชั่ง BLE ปลอมส่ง
  • web/web_main.cpp: WebPlatform (fetch และ download ผ่าน fetch() ของเบราว์เซอร์, การ์ดเป็น MEMFS /card, radio = sim/fake_radio.h) และ WebDisplay 2 buffer ที่ page อ่านเป็น RGB565
  • การตรวจอินเทอร์เน็ตของ OS ไปที่ sim:probe ซึ่ง page ตอบเองตามสวิตช์ internet; fetch ของแอปออกจากเบราว์เซอร์จริง (ติด CORS ได้)
  • registry เริ่มต้นมี Home-WiFi เป็นเครือข่ายที่บันทึกไว้

ชุดตรวจก่อนลงบอร์ด

  1. IOTDASH_DAMAGECHECK=1 RT_CHECK_LAYOUT=1 + script ที่เดินทุกหน้า → ต้องไม่มี damagecheck และ layoutcheck … 0 mismatched
  2. รัน script เดียวกันกับ build ASAN (RT_JS_STACK=256)
  3. IOTDASH_SLOWMEM=1 เพื่อทดสอบเส้นทางอ่านแบบบอร์ด
  4. spincheck บนหน้าที่นิ่ง ต้องได้ 0–1 เฟรม
  5. เทียบภาพกับ Chromium ด้วย os ref

simulator ไม่จำลองเรื่อง bus ของ flash/PSRAM, tear หรือความเร็วจริงของบอร์ด ตัวเลขเวลาใน sim เร็วกว่าบอร์ดหลายเท่า เรื่องเวลาและ glitch ต้องวัดบนบอร์ดเสมอ (ดู การวัดผลและ debug)
