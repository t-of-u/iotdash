ประวัติการพัฒนา

ลำดับงานตั้งแต่เปิดบอร์ดครั้งแรกจนถึง OS ปัจจุบัน พร้อมการตัดสินใจสำคัญและเหตุผล เรียงจากเก่าไปใหม่ (วันที่ตามเวลาไทย)

1. เปิดบอร์ดและ driver จอ 8 ต.ค. 2026

  • บอร์ดไม่ขึ้นเป็น device: ใช้ช่อง USB ที่ต่อชิป CH343 (UART) และเข้าโหมด download ด้วย BOOT + RESET เมื่อ auto-reset ไม่ทำงาน
  • driver RGB 800×480 แบบ bounce buffer เขียนเติมเอง และ benchmark ความเร็วการวาดหลายขนาด
  • ภาพ "ส่าย/เกย": interrupt ของจอย้ายไป IRAM, data cache 64 KB, compile แบบเน้นความเร็ว
  • การตัดสินใจ: วาดผ่าน DMA blitter (CPU วาดลง SRAM, DMA เขียน PSRAM) แทน CPU เขียน PSRAM ตรงๆ ลด traffic ครึ่งหนึ่ง: เต็มจอจาก 20.7 เป็น 39 fps และภาพนิ่งขึ้น จำกัดอัตราเขียน PSRAM เพื่อไม่ให้แย่ง scan-out

2. Engine HTML/CSS/JS บนชิป 8 ต.ค. 2026

  • เป้าหมาย: เขียน UI ด้วย HTML/CSS/JS แล้วรันบนบอร์ดได้ พร้อมการเปลี่ยนหน้า, animation, ภาษาไทย
  • เริ่มจากแนวคิด pre-render ด้วย Chromium แล้วพัฒนาเป็น engine เต็ม (lib/rt): HTML parser, CSS cascade, layout (block/inline/flex/grid/table), QuickJS + Web API, form control, คีย์บอร์ดไทย, SVG, canvas
  • เครื่องมือ build ใช้ Chromium (Playwright) วัดหน้าเพื่อสร้าง font atlas ที่ต้องใช้ ตัดคำไทย และย่อรูป
  • Simulator ใช้โค้ด engine ชุดเดียวกัน
  • ปรับความเร็ว: วาดเต็มจอจาก ~90 ms เหลือ ~27 ms, layout เมื่อนาฬิกาเปลี่ยนจาก 54 ms เหลือ 1.5 ms (partial relayout), เงาเร็วขึ้น ~4 เท่า, blend ใน 565 เร็วขึ้น ~11 เท่า, canvas/SVG cache เป็น layer, วาดสองคอร์ (ตรวจด้วย ThreadSanitizer), แก้ engine ที่ spin 100% ตอนว่าง
  • ข้อสังเกตสำคัญ: ชิปติดที่ cache miss (โค้ดรันจาก PSRAM) มากกว่าการคำนวณ
  • ตั้ง git repo ที่ top/iot (commit ba514b7 Initial commit)

6. แก้ glitch ทั้งระบบ 9 ต.ค. 2026

  • รอบแรก: พบว่าการอ่าน flash ระหว่างวาดแย่ง bus กับ scan-out (F = 1170 late / 2 s, Q = 0) → font เข้า RAM ทีละ glyph, รูปเข้า RAM, อ่านไฟล์แบบ pace, ลด page buffer เหลือ 2 (font ทั้ง atlas ทำ PSRAM หมดจน reboot)
  • ผู้ใช้ยังเห็น glitch → late วัดผิดสิ่ง; ผู้ใช้เสนอแยก layer (scan-out / frame create → push / touch / app)
  • สถาปัตยกรรม 4 layer (ผู้ใช้อนุมัติ):
    1. Scan-out: ตัววัด tear จาก owner bit ของ descriptor + timeline; ปิด RESTART_IN_VSYNC; DMA ของจอ priority สูงสุด → tear 0 (เดิม 12–14 / 3 s)
    2. Frame create → push: เลิก map flash ทั้งหมด (ImageSource/PartitionSource), blitter รอ bus window
    3. Touch: task แยก core 0 ทุก 8 ms ใส่คิวพร้อมเวลา, engine ดึงก่อน app และตื่นทันทีเมื่อมี touch
    4. App: งบ JS 10 ms ต่อ tick, watchdog 3 วินาที, process/interval ที่ค้างถูกปิด
  • commit c191b88 "feat: iot-dash-kernel"

  • เป้าหมาย (phase 1): ให้แอปจริงใช้อินเทอร์เน็ตและอุปกรณ์ Bluetooth LE ได้ โดย OS เป็นเจ้าของการเชื่อมต่อ

  • Settings แท็บ Connection: segment Wi-Fi (สวิตช์, เครือข่ายที่ใช้อยู่, รายการจาก scan พร้อมแถบสัญญาณและกุญแจ, sheet ใส่รหัสที่ Enter ส่งได้, Forget, scan ใหม่เป็นระยะ) และ Bluetooth (สวิตช์, อุปกรณ์ที่จำไว้, อุปกรณ์ใกล้เคียง, connect/disconnect/forget) 4G Cat-1 จะอยู่ในแท็บเดียวกัน (ยังไม่ทำ)
  • Registry: wifi.enabled, bt.enabled, bt.devices, secure.wifi (มองเห็นเฉพาะ system, Settings → System แสดงเป็น ••••••), secure.secretsHash, net.probeUrl; ต่ออัตโนมัติ (เครือข่ายที่ใช้ล่าสุดที่อยู่ในระยะ ทุก 30 วินาทีระหว่างไม่ได้ต่อ) และตรวจอินเทอร์เน็ตทุก 30 วินาที (8 วินาทีหลังล้มเหลว)
  • os/core/private/secrets.json (gitignore) ติดไปกับ system image ที่ system/private/ ซึ่งหน้าเปิดหรือ fetch ไม่ได้ รวมเข้า secure.wifi เมื่อ hash เปลี่ยน
  • JS API os.net / os.wifi / os.bt; การเปลี่ยนการเชื่อมต่อ (wifi.power/connect/disconnect/forget, bt.power/forget) เป็นของ system เท่านั้น frame WIFI ทาง USB เปลี่ยนจากเขียน NVS เองมาผ่าน Os::net
  • SRAM ภายใน: radio ต้องการ SRAM ที่ engine เคยกินไป: malloc() เลือก PSRAM, WiFi TX buffer แบบ dynamic, NimBLE host ใน PSRAM, central 2 link, data cache 64 → 32 KB, bounce buffer 16 → 12 แถว, UART RX ของ dev link 16 → 6 KB (เครื่องมือส่งทีละ 4 KB), stack ของ http ไป PSRAM, task probe สร้างเมื่อใช้ radio ตรวจ SRAM ก่อนเปิดและปฏิเสธแทนการ crash; เปิดทั้งสองแล้วเหลือ ≈48 KB
  • Dev link: frame ที่ขาดกลางทางถูกทิ้งหลังสายเงียบ 500 ms, เครื่องมือจับคู่ ACK กับชนิดของคำขอ (PING ที่ตอบช้าไม่ถูกนับเป็นคำตอบของคำสั่งอื่น)
  • Simulator: เครือข่ายปลอม (Home-WiFi/home1234, TopuTofu/tofu1234, IoT-Lab/iotlab99, Cafe Free WiFi, Neighbor_5G), ตาชั่ง BLE ปลอม BLE-Scale-01 และคำสั่ง scale, scaleoff

12. หน่วยความจำ, HTTPS และ fetch 10 ต.ค. 2026

  • ปัญหา: แอปตาชั่ง ทำให้ PSRAM เหลือ 15 KB บนหน้าแรกแล้ว crash วัดได้ว่าหน้าหนึ่งกิน CSS ≈600 KB, JS context ≈690 KB, script ≈440 KB, การวาดครั้งแรก ≈450 KB (font ≈290 KB)
  • QuickJS ไม่เก็บ source ของ function (QJS_KEEP_FUNCTION_SOURCE = 0, toString ได้รูป [native code]): ≈130 KB ต่อการเริ่มหน้า, ≈160 KB ของ script แอปตาชั่ง
  • CSS: stylesheet ของหน้า parse ครั้งเดียว (เคย parse ใหม่ทุก <link> ระหว่าง parse HTML, Engine::building_), vector ถูก trim, Value ย่อจาก 132 เป็น 68 byte (ส่วนที่ใช้น้อยไปอยู่ใน ValueExt แบบ copy-on-write), ข้อความ keyword เก็บเฉพาะ inline style: CSS ของ แอปตาชั่ง ≈600 → ≈300 KB
  • element ที่ถูกถอดออกจาก document ทิ้ง computed style (≈1.1 KB ต่อตัว) และคำนวณใหม่ถ้ากลับเข้ามา
  • font: ตารางและ glyph ที่อ่านจาก flash ถูกปล่อยเมื่อเปิด document ใหม่ (FontManager::releaseResident) และเมื่อเปลี่ยนแอป เดิมสำเนาของ atlas ระบบค้างและสะสมข้ามแอป; face หนึ่งกินตาราง ≈26 KB (ไทย ≈14 KB)
  • GC ของ JS หลังเปลี่ยนจอ: ถอด node ใต้ wrapper ≥ 150 ตัว + หน้านิ่ง 600 ms (ห่างกัน ≥ 2 วินาที, ≈35 ms บนบอร์ด) เพราะ cycle ของ wrapper ถือ layout/paint ที่ QuickJS ไม่นับ
  • ผลบนบอร์ด: หน้าแรกของ แอปตาชั่ง 15 KB → ≈850–960 KB; ทั้ง flow ≈465 KB คงที่ 20 รอบ (เดิมลด ≈5 KB ต่อรอบ) ภาพเหมือนเดิมทุก pixel ใน sim และผ่าน ASAN; เพิ่มคำสั่ง mem ใน sim และ heap บนบอร์ด
  • HTTPS: mbedtls_ssl_setup ล้มด้วย -0x7F00 (หน่วยความจำไม่พอ) เมื่อเปิด radio แก้ด้วย CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC=y (buffer ของ TLS ใน PSRAM)
  • fetch บนบอร์ด: ใช้ esp_http_client แบบ stream (open/write/fetch_headers/read) คำตอบ 4xx/5xx จึงถึงหน้าพร้อม body (เดิม 401 กลายเป็น ESP_ERR_NOT_SUPPORTED), ตาม redirect ไม่เกิน 5 ครั้ง (301/302/303 ไปต่อเป็น GET), stack ของ task http 10 KB ใน PSRAM
  • shadow ที่จอง mask ไม่ได้ถูกข้ามแทนการ crash

13. แก้จากการทดสอบกับ server และตาชั่งจริง 10 ต.ค. 2026

  • บอร์ด reset หลัง login (ต่อ Wi-Fi + ตาชั่ง BLE): task http copy คำตอบขนาด 174 KB แล้ว operator new จองไม่ได้จึง abort แก้: จอง body ครั้งเดียวจาก Content-Length, ตรวจที่ว่างก่อนขยาย (ไม่พอ = fetch ล้มด้วย ESP_ERR_NO_MEM ไม่ใช่ reset), move คำตอบแทน copy, operator new พิมพ์ขนาดและที่ว่างก่อน abort
  • engine: ความกว้าง max-content ของกล่อง border-box ไม่นับ padding ที่เกิน width (ข้อความใน popup ขึ้น 2 บรรทัดจนปุ่มหลุดกรอบ)
  • engine: บรรทัดที่ยาวเกินกล่องชิดขอบเริ่มต้นแม้ text-align: center (ตาม CSS Text และ Chrome เดิมตัดหัวข้อความ)
  • ไอคอน SVG เบี้ยว/เส้นผิด: subpath ที่ไม่ปิดถูก stroke เป็นรูปปิด (ลูกศร "เปลี่ยนอุปกรณ์" กลายเป็นสามเหลี่ยม, คลื่น Wi-Fi เป็นเสี้ยวทึบ) และ stroke-linecap/linejoin จาก CSS ไม่มีผล (จุดหายไป ปลายเส้นตัด) แก้ใน Path และเพิ่มสอง property นี้ใน CSS ตรวจไอคอน 47 ตัวของแอปตาชั่งและ 18 ตัวของระบบเทียบกับ Chromium
  • จอกระพริบ/เลื่อนวูบตอนกดหรือเปลี่ยนหน้า: interrupt ของจอย้ายจาก core 0 (ร่วมกับ Wi-Fi/Bluetooth) ไป core 1: late 10 → 0, tear 25 → 7 ใน flow ทดสอบ
  • กดไอคอนที่หน้า home แล้วไอคอนเบี้ยวไปทางขวา: รูปที่มี transform ถูกวาดด้วยส่วนเลื่อนของ matrix อย่างเดียว (scale(.9) จึงกลายเป็นเลื่อน ~9 px ไปขวาล่างโดยไม่ย่อ) และเงาหายระหว่าง transform ตอนนี้รูปถูก sample ผ่าน matrix เต็ม (fillPath + image paint) และเงาย่อ/ขยายตามเมื่อ transform มีแค่เลื่อนกับ scale; ท่ากดของ home ปรับใหม่: กดลง 0.08 วินาทีเป็น 90% และจางลงเล็กน้อย ปล่อยแล้วเด้งกลับ 0.22 วินาที
  • Wi-Fi ที่บันทึกไว้ขึ้นว่ารหัสผิดหลัง reboot: handshake ล้มครั้งแรกหลัง boot ถูกสรุปว่ารหัสผิดทันที (และหยุดการลองซ้ำของ driver) ตอนนี้ต้องล้ม 3 ครั้งติดกัน

  • บอร์ด: Platform::download (stream ลง sink, ทั้งบอร์ด/desktop sim/เว็บ), lib/rt/os_store.cpp (เขียนระหว่างโหลด, ตรวจ checksum, staging, แทนไฟล์โดยข้อมูลอยู่ครบ), os.store, event install, install.json บอกที่มา (store/usb), os.apps() มี source/versionId
  • แอป Apps (system): Store / Installed, ป้ายที่มา, เวอร์ชันทั้งหมดของแต่ละแอป, ติดตั้ง/อัปเดต/ย้อนเวอร์ชัน/ลบ, ความคืบหน้า + ยกเลิก, รายการ offline
  • Backend (store/backend): Lambda Python 3.13, DynamoDB iotstore-users/-projects/-versions, ไฟล์ใน S3 (อัปโหลดตรงจากเบราว์เซอร์ด้วย presigned POST), runner ในเครื่องด้วย moto
  • เว็บ (store/frontend, React + Vite): project, เวอร์ชัน (อัปโหลด, notes, publish, ดาวน์โหลด, ลบ), ตรวจแพ็กเกจในเบราว์เซอร์ก่อนส่ง, หน้า Simulate
  • Simulator บนเบราว์เซอร์ (web/): engine + OS เป็น WebAssembly วาดลง canvas, Wi-Fi/อินเทอร์เน็ตจำลอง, อุปกรณ์ BLE และเกมตาชั่ง: ลากขวดพลาสติก แก้ว กระดาษ โลหะ ขึ้นจาน ค่าขึ้นแบบสปริงหน่วง (เกินนิดแล้วนิ่ง, STABLE) ส่งให้แอปผ่านตาชั่ง BLE จำลอง
  • ทดสอบ: ติดตั้ง/อัปเดต/ล้มกลางทาง (checksum เสีย, ไฟล์ขาด, 404, id ผิด) ใน desktop sim; เว็บครบ flow ใน Chromium headless; บอร์ดจริงอัปเดตแอปขนาด 481 KB จาก 1.0 → 1.1 จาก backend ในเครื่องใน 5.3 วินาที

15. SDK และ store แบบ framework 10 ต.ค. 2026

iotdash เป็น SDK (แบบ Flutter) และ iotstore เป็น store ที่ใครก็ host เองได้ ส่วนแอปเป็นของผู้เขียนและอยู่นอก repo

  • command line bin/iotdash (ใส่ใน PATH, สร้าง tools/.venv เองครั้งแรก) และ scripts/setup.sh: create, run (simulator / --device / --web), build, pack, install, uninstall, apps, publish, shot, doctor, firmware; คำสั่งยุคก่อน OS ย้ายไป iotdash legacy
  • แอปเป็นโปรเจกต์ที่ไหนก็ได้ (tools/project.py): app.json มี id, ผลการ build อยู่ใน <project>/build/, ไฟล์ของโปรเจกต์ (README, LICENSE, icon) ไม่เข้า image; os/apps/ และ install.sh/uninstall.sh ถูกแทนด้วย examples/ + templates/app/ + CLI
  • แยกของที่ไม่ใช่ของ SDK ออก: แอปตาชั่ง (เดิม os/apps/digital-scales) เป็นโปรเจกต์ภายนอกที่ build ด้วย SDK เหมือนแอปอื่น; ชื่ออุปกรณ์จำลองเป็นกลาง (Home-WiFi, BLE-Scale-01)
  • iotstore แบบ host เอง: deploy.env + scripts/deploy.sh (สร้างหรืออัปเดต table, bucket + CORS, role, layer, function, function URL ในคราวเดียว, --dry-run, เก็บ JWT key เดิม) และ scripts/deploy-web.sh; ทุกอย่างตั้งชื่อตาม STORE_NAME (หลาย store ในบัญชีเดียวได้); CORS_ORIGIN หลาย origin, SIGNUP=open|closed, ชื่อ store มาจาก API; ทดสอบ deploy ครบสองรอบกับ AWS จำลอง (moto server)
  • store เป็นส่วนหนึ่งของ SDK: ย้ายจาก iotstore/ มาที่ iotdash/store/ และสั่งผ่าน CLI: iotdash store dev (API + เว็บ), test, deploy [--dry-run] [--config], deploy-web; iotdash doctor ตรวจเครื่องมือของ store ด้วย

16. Kiosk mode 12 ต.ค. 2026

  • แอป Apps: ปุ่ม ⋮ ข้าง Open → เมนู Kiosk mode → sheet ใส่รหัสผ่านสองครั้ง (อย่างน้อย 4 ตัว) → แอปนั้นเป็นหน้าจอเดียวของบอร์ด เปิดเองตอนเริ่มระบบ
  • OS (lib/rt/os_kiosk.cpp): Home, Back ที่หน้าแรก และ os.home() ถามรหัสผ่านผ่าน dialog ของระบบที่มีช่องรหัสผ่าน ("Wrong password" / Cancel / ถูก = ปิด kiosk แล้วกลับ home); เก็บ salt + SHA-256 ใน secure.kiosk; os.kiosk.status/start
  • Engine: ช่องกรอกของ system UI (internal) ไม่ส่ง focus/blur/input/change/keydown ให้ script ของหน้า; OsHooks::internalKey ให้ OS รับ Enter; ระหว่าง dialog รหัสผ่าน touch ที่ไม่ใช่ของ dialog ไปที่ keyboard ของ engine
  • ลืมรหัสผ่าน: iotdash device kiosk-off (frame 19 KIOSK_OFF), ใน sim: kioskoff
