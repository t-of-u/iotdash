สิ่งที่ยังไม่สมบูรณ์, ข้อจำกัดที่ตั้งใจ, และงานที่รอการตัดสินใจ ณ วันที่ 10 ต.ค. 2026

รอการตัดสินใจ

ค่าในแอปยังอยู่หลังกลับ home รอตัดสินใจ

อาการ: เปิด Calculator พิมพ์ตัวเลข กด home แล้วเปิดใหม่ ตัวเลขเดิมยังอยู่

สาเหตุ: ไม่ใช่ cache: แอปปิดจริง (JS session จบ, image ถูกปล่อย) แต่ Calculator เก็บ expr/ans ใน localStorage ซึ่งคือไฟล์ memory.json แบบถาวร เพื่อให้หน้า Scientific/History เห็นค่าเดียวกัน (เพราะแต่ละหน้าเป็น JS context ใหม่) sessionStorage ตอนนี้เป็นของแต่ละหน้าจึงใช้ข้ามหน้าไม่ได้

ข้อเสนอ: ให้ OS มี sessionStorage ระดับแอป: ใช้ร่วมทุกหน้าของแอป, อยู่ในหน่วยความจำ, ล้างเมื่อออกจากแอป แล้วให้ Calculator ใช้ sessionStorage สำหรับค่าบนจอ (คง history และ count ไว้ใน storage ถาวร)

สถานะ: ยังรอคำตอบจากผู้ใช้ (10 ต.ค.) ยังไม่ได้เปลี่ยนอะไรใน OS

เรื่องสถานะทางเลี่ยง
ช่อง SD ของบอร์ดที่ใช้พัฒนาเสียฮาร์ดแวร์ หน้าสัมผัสไม่แตะการ์ด; firmware ทางการก็อ่านไม่ได้ใช้ LittleFS ใน flash (5.2 MB); ส่งเคลมพร้อมผล SD_Test.bin และผลวัด; หรือโมดูล SD ภายนอก
เส้นทาง SD ยังไม่ได้ทดสอบบนบอร์ดจริงยังไม่ทดสอบ ทดสอบเฉพาะใน simulator และ LittleFSทดสอบเมื่อได้บอร์ด/ช่องที่ใช้ได้ (mount, format, ความเร็วคัดลอก image)

เปิด serial port แล้วบอร์ด resetสาย DTR/RTS ต่อกับ EN/IO0 การเปิดพอร์ตทุกครั้งทำให้บอร์ด boot ใหม่เครื่องมือรอจนบอร์ดตอบ PING ("ready") ก่อนทำงาน; งานหลายขั้นทำใน connection เดียว

Wi-Fi และ Bluetooth

เรื่องรายละเอียดแนวทาง
Packet ของ dev link หายบ้างเมื่อเปิด Wi-Fiบางครั้ง frame ไม่ถึงบอร์ดหรือคำตอบไม่กลับ บอร์ดทิ้ง frame ที่ขาดกลางทางเมื่อสายเงียบ 500 ms; wait_ready ส่ง PING ซ้ำจนบอร์ดตอบ แต่คำสั่งที่ส่งไปแล้วไม่ได้ ACK (เช่น chunk ของ FS_WRITE) ยังไม่มีการส่งซ้ำอัตโนมัติ: เครื่องมือหยุดด้วย "no answer from the board"รันคำสั่งใหม่; ถ้าเกิดบ่อยควรเพิ่ม retry ต่อ chunk ใน DeviceCard
SRAM ภายในสำหรับ radioเปิด Wi-Fi + BLE แล้ว SRAM เหลือ ≈48 KB; radio ปฏิเสธถ้าเหลือไม่ถึง 34 KB (Wi-Fi) / 30 KB (BLE)ของใหม่ที่ต้องอยู่ใน SRAM ต้องวัดด้วย heap ก่อน
รหัส Wi-Fi ไม่ได้เข้ารหัสอยู่ใน registry (NVS) และใน os.idb (จาก secrets.json) แบบ plain text ซ่อนจาก script ของแอปเท่านั้นNVS encryption / flash encryption ถ้าต้องการ
Bluetooth LE แบบจำกัดcentral เท่านั้น, ต่อพร้อมกัน 2 อุปกรณ์, ไม่มี pairing/bonding, ข้อมูลต่อครั้งไม่เกิน 512 byte–
Wi-Fi2.4 GHz เท่านั้น, ไม่แสดงเครือข่ายที่ซ่อนชื่อ, ไม่มี WPA-Enterprise / captive portal login–
4G Cat-1วางแผนไว้ในแท็บ Connection เดียวกันยังไม่ได้ทำ

ประสิทธิภาพและหน่วยความจำ

เรื่องรายละเอียดแนวทาง
Paint ของปุ่มที่มี transform ~25 msCalculator กดปุ่ม: :active { transform: scale(.95) } + shadow ทำให้ paint เป็นส่วนที่ช้าที่สุดของ ~31 mscache ของกล่องที่ transform, หรือใช้ effect ที่ถูกกว่า (เปลี่ยนสีพื้น)
JS realm เก่าค้าง ~400 KBAPP process ที่สร้างในหน้าแรกถือ closure ของ realm นั้นไว้ PSRAM ต่ำสุดเคยเหลือ ~270 KB (ก่อนแก้ shadow cache) / ~480 KB (ปัจจุบัน) ตอน modal ทับหน้า Historyให้ APP process รันใน realm กลางของแอป หรือแนะนำให้สร้างจากไฟล์ที่ไม่อ้าง DOM
2 page bufferเฟรมที่ใช้เวลาเกิน ~25 ms เสียหนึ่งรอบจอ-DRGB_PAGES=3 เมื่อ PSRAM พอ (ต้องการ 750 KB + 1.5 MB ว่าง)
Glyph/รูปถูกข้ามเมื่อหน่วยความจำต่ำfont ไม่คัดลอกถ้าเหลือ < 256 KB, สำเนารูป < 384 KB: ข้อความบางตัวอาจหายตั้งใจ (ดีกว่าระบบล่ม); ดู psram ใน stats
font ขนาดใหญ่ (> 34 px) มีเฉพาะตัวที่เห็นตอน buildข้อความที่ JS สร้างใหม่ที่ขนาดนั้นอาจไม่มี glyphใส่ตัวอักษรตัวอย่างไว้ในไฟล์ของแอป เช่น element ที่ display: none (build อ่าน font ของ element ที่ซ่อนด้วย)
ตาราง font ≈26 KB ต่อ faceทุก (weight, size) ที่หน้าใช้ถือ glyph metrics ≈4.5 KB + kerning ≈6.5 KB + ตำแหน่งสระไทย ≈14 KB ตลอดเวลาที่หน้าเปิด (หลังงานรอบ แอปตาชั่ง ถูกปล่อยเมื่อเปลี่ยนหน้า)ใช้ขนาดของระบบ; ถ้าต้องลดอีก: โหลดตารางไทยเฉพาะ face ที่มีข้อความไทย หรือย่อตาราง
GC หลังเปลี่ยนจอ ≈35 msเมื่อ node ใต้ wrapper ถูกถอด ≥ 150 ตัว ระบบเรียก JS_RunGC หลังหน้านิ่ง 600 ms (ห่างกัน ≥ 2 วินาที) อาจเห็นเป็นการตอบสนองช้าหนึ่งครั้งถ้าแตะตรงจังหวะนั้นตั้งใจ (แลกกับ PSRAM ที่คงที่); ปรับเกณฑ์ใน JsHost::tick ถ้าจำเป็น
Function.prototype.toString ไม่มี sourceQuickJS ไม่เก็บ source ของ function (ประหยัด ≈130 KB ต่อหน้า)ตั้งใจ; build ใหม่ด้วย -DQJS_KEEP_FUNCTION_SOURCE=1 ถ้ามี library ที่ต้องใช้
ดาวน์โหลดแอปบัง fetch อื่นboard มี worker ของ HTTP ตัวเดียว ระหว่างติดตั้งจาก store (ไม่กี่วินาทีต่อ 500 KB) fetch ของหน้าเข้าคิวรอ (คิว 8 งาน)worker ตัวที่สองสำหรับ download ถ้า SRAM ภายในพอ (TLS อีกชุด)
Firmware ใช้ partition app0 91.5%3.78 MB จาก 4.03 MB หลังเพิ่ม storeขยาย app0 (flash 16 MB ยังว่าง) ก่อนเพิ่มของใหญ่
ขนาด imageแอป ≤ 1.5 MB, ระบบ ≤ 2.25 MB (ปัจจุบัน ~1.77 MB, Calculator ~864 KB, แอปตาชั่ง ~465 KB)ใช้ font ของระบบ, ย่อรูป

ต้องยืนยันบนบอร์ดด้วยมือจริง

  • การตอบสนองของ Calculator หลังแก้ invalidation (~31 ms ต่อการกด) ทดสอบผ่าน USB tap และ log แล้ว แต่ยังรอผลจากนิ้วจริง
  • การปัดแถบล่างและการแตะเร็วๆ ผ่าน touch task ใหม่
  • ความรู้สึกของ glitch: ตัวนับ tear เป็น 0 เกือบทุกสถานการณ์ (ดูข้อถัดไป) แต่การมองจริงเป็นตัวตัดสินสุดท้าย
  • interrupt ของจอย้ายไป core 1 แล้ว (ห่างจาก radio): ใน flow ทดสอบ late 10 → 0 และ tear 25 → 7 ครั้ง tear ที่เหลือเกิดช่วงเปิดหน้า (load) ตอนอ่าน font/รูปจาก flash ยังควรลดต่อ (pacing หรือ bounce buffer 16 แถวถ้ามี SRAM ภายในพอ)
  • bounce buffer เหลือ 12 แถว (งบเวลาต่อ buffer ~615 µs จาก ~820 µs): ใช้ แอปตาชั่ง ครบ flow ขณะ Wi-Fi ทำงาน (login, เลือกสถานที่, วัสดุ, สรุป วน 20 รอบ) สองรอบ รอบแรก tears 0 รอบที่สอง tears 5 เกิดครั้งเดียวตอนเข้าหน้าชั่งครั้งแรก ทั้งหมดอยู่ในช่วงอ่าน flash (io 4, idle 1) ขณะโหลดตาราง font ตัวเลขใหญ่ ส่วน late เป็น 0 ทั้งสองรอบ ตอนนี้ตาราง font ถูกอ่านจาก flash ใหม่ทุกครั้งที่เปิดหน้า (แลกกับ RAM) จึงควรเฝ้าดูว่า tear ช่วงเปิดหน้าเพิ่มขึ้นหรือไม่ ยังไม่ได้วัดใหม่กับ stress f

iotstore

  • ทดสอบกับ backend ในเครื่อง (moto + Flask, HTTP) ครบทุกขั้นทั้ง simulator, เว็บ และบอร์ดจริง กับ S3 จริง: ลายเซ็นของ presigned GET/POST ผ่าน (S3 ตอบ NoSuchKey / ตรวจ policy) และ desktop simulator โหลดผ่าน HTTPS ได้ ยังไม่ได้ลองบนบอร์ด (ผ่าน TLS ไป <bucket>.s3.ap-southeast-1.amazonaws.com; บน Lambda URL ยาว ~1.5 KB เพราะมี session token: ขยาย buffer ส่งของ download เป็น 3 KB แล้ว)

ข้อจำกัดของ API

  • ไฟล์ที่ open() แล้วไม่ปิด จะค้างจนออกจากแอป (ไม่ผูกกับ scope ของหน้า)
  • history.go(-n) ย้อนได้ทีละหนึ่งหน้า
  • การย้อนกลับเปิดหน้าใหม่ ไม่คืน DOM/สถานะ JS เดิม
  • registry เขียนได้เฉพาะ system app (ไม่มีระบบขอสิทธิ์)
  • ไม่มีการจำกัดขนาด memory.json หรือ data/ ต่อแอป
  • fetch ภายนอกต้องมี Wi-Fi; รหัส Wi-Fi เก็บใน registry แบบไม่เข้ารหัส (ซ่อนจากแอป)
  • แอปเปลี่ยนการเชื่อมต่อเองไม่ได้ (เปิดปิด radio, เลือกเครือข่าย): ต้องส่งผู้ใช้ไป Settings
  • simulator ไม่จำลอง bus, tear และความเร็วจริงของบอร์ด
