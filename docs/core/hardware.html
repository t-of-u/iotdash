Flash และ PSRAM ใช้ bus MSPI เดียวกัน ทุกครั้งที่อ่านหรือเขียน flash (โค้ดหรือข้อมูล) bus จะไม่ว่างให้ DMA ดึงภาพจาก PSRAM ไปที่จอ ข้อเท็จจริงนี้เป็นที่มาของการออกแบบหลายอย่างใน การแสดงผล และ หน่วยความจำ

IO expander CH422G

CH422G ไม่มี I2C address ปกติ แต่ละ "address" คือคำสั่ง: 0x24 (WR_SET, bit0 = ให้ EXIO0–7 เป็น output), 0x38 (WR_IO, ระดับของ EXIO0–7), 0x26 (RD_IO, อ่านระดับขาจริงกลับมา ใช้ตรวจว่า CS เปลี่ยนจริง)

ลำดับการเริ่มต้นใน setup()

  1. devlink.begin(921600): dev link บน UART0 พร้อมรับคำสั่งตั้งแต่แรก
  2. I2C → CH422G (LCD_RST | SD_CS = high) → GT911 (reset ผ่าน EXIO1)
  3. sd.begin(): เตรียม SPI2 ก่อนจอ เพราะ GDMA แบบ memory-to-memory (fill และ blitter) ต้องยืม trigger id ของ peripheral ที่ว่าง และ SPI2 ต้องได้ของตัวเองก่อน
  4. lcd.begin(16 MHz) → dma.begin() → dma.setScanOut(&lcd) (blitter รู้จังหวะของ scan-out)
  5. Paint helper task (core 0, stack 9 KB), touch queue + touch task (task probe ถูกสร้างเมื่อสั่ง probe ครั้งแรก)
  6. เปิด backlight → plat.begin() (Preferences "iotdash", fetch worker "http" ที่ stack อยู่ใน PSRAM, ต่อ callback ของ radio::begin)
  7. สร้าง engine task 48 KB บน core 1 แล้วลบ Arduino loop task ทิ้งเพื่อคืน stack

firmware ไม่ต่อ Wi-Fi เองแล้ว: OS เปิด radio หลังโหลด registry (Os::netStart) ตาม wifi.enabled และเครือข่ายที่บันทึกไว้ ส่วน Bluetooth เปิดเมื่อมีคนใช้ ดู Wi-Fi และ Bluetooth

ค่า build และ sdkconfig

ใช้ pioarduino (Arduino บน ESP-IDF 5) แบบ hybrid compile เพื่อให้ตั้ง sdkconfig เองได้

ค่าเหตุผล
CONFIG_LCD_RGB_ISR_IRAM_SAFE=yinterrupt ของ panel อยู่ใน IRAM ทำงานได้แม้ cache ถูกปิดระหว่างเขียน flash
'# CONFIG_LCD_RGB_RESTART_IN_VSYNC is not set'ปิด restart ทุก vsync เพราะ driver ไม่ reset ตัวนับ bounce buffer ทำให้ EOF ที่หลงมาเติม buffer ผิด ภาพทั้งเฟรมเลื่อน 16 แถว (รายละเอียดใน การแสดงผล) ต้องใส่ quote เพราะใน ini เครื่องหมาย # ที่ไม่มี quote คือ comment และการลบบรรทัดทิ้งไม่พอ เพราะค่า default ของ Arduino คือ =y
CONFIG_ESP32S3_DATA_CACHE_32KB, LINE_64Bline 64 B ให้ throughput ของ PSRAM สูงขึ้น; ขนาดลดจาก 64 KB เป็น 32 KB ตอนเพิ่ม radio (cache ของ S3 ใช้ SRAM ภายใน) comment ด้านบนของ custom_sdkconfig ใน platformio.ini ยังเขียนว่า 64 KB
CONFIG_ESP32S3_INSTRUCTION_CACHE_32KBลด cache miss ของโค้ด
CONFIG_SPIRAM_XIP_FROM_PSRAM=yโค้ดและ rodata รันจาก PSRAM ดังนั้นการเขียน flash (คัดลอก image, localStorage) ไม่ปิด cache ใต้ interrupt ของ scan-out และการรันโค้ดไม่ไปแย่ง flash
CONFIG_COMPILER_OPTIMIZATION_PERF, -O2 (ตัด -Os)ความเร็วของ layout/paint/JS
CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=0malloc() ทั่วไปเลือก PSRAM ทุกขนาด: การจองเล็กๆ ของ engine เคยกิน SRAM ภายในที่ WiFi, Bluetooth และ stack ต้องใช้ (พวกนั้นขอ internal ด้วย capability เอง)

พอร์ต USB และ dev link

  • ใช้พอร์ต USB ที่ต่อกับชิป USB-serial (ที่ macOS เห็นเป็น /dev/cu.usbmodem5B901262921) ความเร็ว 921600 baud
  • การเปิดพอร์ตจะ reset บอร์ด (DTR/RTS) เครื่องมือจึงรอให้บอร์ดตอบ PING ก่อนส่งงาน
  • buffer รับของ UART เหลือ 6 KB (SRAM ภายใน) เครื่องมือส่ง frame ละไม่เกิน 4 KB แล้วรอคำตอบ; frame ที่ขาดกลางทางถูกทิ้งเมื่อสายเงียบ 500 ms
  • ถ้า upload ขึ้น "No serial data received" ให้ลองใหม่ หรือกด BOOT ค้างแล้วกด RESET เพื่อเข้า download mode
  • เปิดพอร์ตได้ทีละโปรแกรม ถ้า device log หรือ device probe ค้างอยู่ คำสั่งอื่นจะใช้พอร์ตไม่ได้ (ต้อง Ctrl-C ก่อน)

Probe วัดแรงดัน (Sensor AD)

เพิ่มไว้ตอนตรวจช่อง SD: task probe (core 0, priority 1) อ่าน GPIO6 ด้วย ADC (attenuation 11 dB, อ่านได้ถึง ~3.1 V) ประมาณ 10 บรรทัดต่อวินาที และรายงาน avg/min/max ในช่วง 100 ms พร้อมสถานะ HIGH/LOW/TOGGLING และสถานะสาย SD

probe GPIO6: 3105 mV  min 3098  max 3112  HIGH     | cs low sck 1 mosi z miso z
  • ต่อสายจาก J8 ขา 3 ไปแตะจุดที่จะวัด (GND ร่วมกันอยู่แล้ว)
  • ห้ามแตะจุด 5 V (VBUS, แบตเตอรี่) ขา ADC ทนไม่ถึง 5 V
  • คำสั่ง: iotdash.py device probe [cs0|cs1|sck0|sck1|sckz|mosi0|…] ดู คำสั่งบนบอร์ด

ช่อง SD card ของบอร์ดที่ใช้ทดสอบเสีย

สรุป: ช่องเสียบ SD ของบอร์ด Rev 1.2 ตัวที่ใช้พัฒนาอ่านการ์ดไม่ได้ (sdmmc_card_init failed (0x107) = timeout) ไม่ใช่ปัญหาของโค้ด ระบบจึงใช้ flash ภายในแทนการ์ดไปก่อน
