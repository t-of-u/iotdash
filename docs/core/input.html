Touch และ input

เส้นทางของการแตะหนึ่งครั้ง ตั้งแต่ชิป GT911 จนถึง click ในแอป: task อ่าน touch ของตัวเอง, คิวพร้อมเวลาที่ sample, gesture ของ OS, InputController (ลาก, scroll, คลิก) และวิธี debug ด้วย ilog

Touch task (layer 3)

  • task touch บน core 0 priority 6 (สูงกว่า paint helper) อ่านชิปทุก 8 ms (~120 Hz) ด้วย vTaskDelayUntil ไม่ว่า engine จะทำอะไรอยู่
  • ใช้จุดแรกจากสูงสุด 5 จุด; ส่ง DOWN เมื่อเริ่มแตะ, MOVE เมื่อพิกัดเปลี่ยน, UP เมื่อปล่อย (ที่พิกัดสุดท้าย)
  • แต่ละ event มี esp_timer_get_time() ตอน sample ติดไปด้วย
  • ถ้าคิวเต็ม (engine ค้าง): MOVE ถูกทิ้ง แต่ DOWN/UP จะดัน event เก่าสุดออกแทน ไม่ให้การกด/ปล่อยหาย
  • การแตะจำลองผ่าน USB (device tap, dev-link TOUCH) ใส่ลงคิวเดียวกัน จึงวิ่งเส้นทางเดียวกับนิ้วจริง

การรับ event ใน engine loop

while (true) {
  devlink.poll();          // phase io
  drainTouch();            // phase input: ทุก event ในคิว → eng->pointerAt(…, sampleUs)
  bool drew = eng->update();
  if (!drew) xQueuePeek(touchQ, …, idle ≤ 16 ms);   // หลับ แต่ตื่นทันทีเมื่อมี touch
}

touch ถูกส่งก่อน app process เสมอ เพราะแอปต้องเห็นพื้นที่กด (layout ล่าสุด) ก่อนจึงตรวจได้ว่าแตะโดนอะไร pointerAt() ตั้งเวลาของ event (eventUs_) เป็นเวลาที่ sample จริง ความเร็วของ scroll และ gesture จึงคำนวณจากเวลาจริง ไม่ใช่เวลาที่ engine ว่างมาอ่าน

ชั้น OS ได้ก่อน

Engine::pointer() ตั้ง watchdog ของ JS แล้วถาม Os::pointer() ก่อน ถ้า OS รับไว้ แอปจะไม่เห็น event นั้นเลย

สถานการณ์OS ทำอะไร
dialog เปิด หรือกำลังเปิดแอปรับทุก touch (exclusive) ปุ่มใน dialog ทำงานตอน UP ถ้ายังอยู่บนปุ่มเดิม
แถบล่างแสดงอยู่ และแตะปุ่ม home/backรับไว้, ต่อเวลาซ่อนแถบอีก 3.5 วินาที, ทำ action ตอน UP
DOWN ในแถบ 18 px ล่างสุด (อยู่ในแอป)เริ่ม gesture; ถ้าลากขึ้นเกิน 24 px จะแสดงแถบล่าง; รับ event ของนิ้วนั้นทั้งหมด
อื่นๆส่งต่อให้ InputController

InputController

DOWN

  • flush layout แล้ว hit-test หา target (ถ้าไม่โดนอะไรใช้ <body>)
  • ตั้ง :active ให้ target (และบรรพบุรุษ ตาม CSS) ส่ง pointerdown, touchstart, mousedown
  • form control (slider ฯลฯ) อาจ "capture" pointer ไว้ (captured_)
  • DOWN ที่ห่างขอบซ้ายไม่เกิน 16 px เริ่ม swipe-back ได้

MOVE

  • ยังไม่ถือเป็นการลากจนเลื่อนเกิน 9 px (kSlop)
  • เมื่อเกิน: หา scroll container ในทิศที่ลาก (ลองทิศหลักก่อน แล้วทิศตั้งฉาก) ถ้าเจอ จะเริ่ม scroll, ยกเลิก :active และส่ง pointercancel/touchcancel (คลิกจะไม่เกิด)
  • ถ้าไม่มีอะไร scroll ได้: ส่ง pointermove/touchmove/mousemove ต่อ และถ้าเลื่อนเกิน 24 px คลิกจะถูกยกเลิก
  • เก็บ sample 120 ms ล่าสุดไว้คำนวณความเร็ว

UP

  • swipe-back: ลากไปทางขวาเกิน 90 px จากขอบซ้าย → ย้อนหน้า
  • หลัง scroll: momentum ถ้าความเร็ว > 40 px/s หรือ snap ไปจุด scroll-snap-align ที่ใกล้ตำแหน่งที่ momentum จะพาไป (ใช้ใน home screen)
  • ไม่ได้ scroll: ส่ง pointerup/touchend/mouseup แล้วส่ง click ถ้าคลิกไม่ถูกยกเลิก และจุดที่ปล่อยยังอยู่บน target เดิม (หรือลูก/บรรพบุรุษของมัน)
  • ถ้า click ไม่ถูก preventDefault() จะทำ default action: ลิงก์, form control, label, summary, blur

ข้อแนะนำสำหรับแอป

  • ใช้ click สำหรับปุ่มทั่วไป จะได้พฤติกรรมยกเลิกเมื่อลาก/scroll ที่ถูกต้อง
  • ใช้ pointerdown เมื่อต้องการตอบสนองทันที (เช่นปุ่มเครื่องคิดเลข) แต่ต้องจัดการการลากเอง
  • ทำปุ่มให้ใหญ่พอ (≥ 44 px) ความละเอียดของ touch บนจอนี้ไม่ได้แม่นระดับ pixel
  • อย่าวาง element ที่ต้องแตะไว้ใน 18 px ล่างสุด เพราะเป็นพื้นที่ของ gesture เปิดแถบล่าง (ในแอป)
  • หลีกเลี่ยง selector แบบ .row:active .label หรือ :active ~ x เพราะทำให้การกดต้อง restyle subtree/พี่น้อง (ดู invalidation)

Debug: ilog

คำสั่ง text ilog สลับ flag DBG_INPUT (0x10) แล้ว log ทุกขั้น:

touch: DOWN 412,301 (sampled 3 ms ago)
input: down 412,301 -> <div class=key> (5 ms late)
touch: UP 412,301 (sampled 2 ms ago)
input: click <div>
input: up 120,460: no click (moved 31,2)
input: down 400,470 -> system

ใช้แยกปัญหาได้ว่า touch มาถึงช้า (sampled … ago สูง), ไปโดน element ผิด, ถูก OS รับไป, หรือคลิกถูกยกเลิกเพราะลาก

กรณีศึกษา Calculator "กดไม่ติด": log จากนิ้วจริงแสดงว่าทุกการกดถึงแอปครบ (click ทุกครั้ง) แต่ engine ใช้ ~130 ms ต่อการกด และการแตะแรกหลังเปลี่ยนหน้ารอคิว 450–530 ms จึงรู้สึกเหมือนกดไม่ติด ต้นเหตุคือ restyle/relayout ทั้งหน้า ไม่ใช่ input แก้แล้วเหลือ ~31 ms (ดู Rendering engine)
