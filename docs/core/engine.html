แกนระบบ (core)

Rendering engine

engine HTML/CSS/JS ที่เขียนเองทั้งหมดใน lib/rt/ (~21,000 บรรทัด C++): parse HTML, cascade CSS, layout (block, inline, flex, grid, table), วาดเฉพาะส่วนที่เปลี่ยน, animation, form control, SVG, canvas, font ที่ rasterize ไว้ล่วงหน้าพร้อมรองรับภาษาไทย โค้ดเดียวกันรันทั้งบนบอร์ดและใน simulator

วงจรของหนึ่ง tick

Engine::update() ถูกเรียกจาก engine loop (core 1) หลังส่ง touch เข้ามาแล้ว แต่ละขั้นตั้ง gPhase ไว้ เพื่อให้ตัววัด tear บอกได้ว่าเกิดระหว่างขั้นไหน

  1. ตั้ง JS watchdog (kScriptWatchdogMs = 3000), pollAsync() (ผล fetch), งานที่ถูก post ไว้ script
  2. Os::tick(): boot step, งาน deferred, โหลด app image, ซ่อนแถบล่าง, flush memory.json os
  3. input_->tick() (momentum scroll), widgets_->tick(), js_->tick() (timer, background process ภายใต้งบ 10 ms) script
  4. เปิดหน้าที่รออยู่ (openLater) load
  5. เดิน animation และเขียนค่าลง computed style layout
  6. ถ้าไม่มีอะไรเปลี่ยน → คืน false (loop จะหลับรอ touch หรือ timer สูงสุด 16 ms)
  7. requestAnimationFrame callbacks
  8. render(): style → layout → build display list → เก็บ damage → วาด band → present หรือ transition paint

Invalidation: ทำงานเท่าที่จำเป็น

Style

  • flag ต่อ node: NF_STYLE_DIRTY (ตัวเอง), NF_SUBTREE_STYLE (ทั้ง subtree), NF_DESC_STYLE_DIRTY (มีลูกหลานที่ dirty) restyle เดินเฉพาะเส้นทางที่ dirty
  • StyleEngine::rebuildIndex() แบ่ง rule ตาม id/class/tag/universal และตรวจ stylesheet ทั้งหมดว่า:
    • มี sibling combinator (+, ~) หรือ :has() ไหม → gSiblingSelectors
    • มี pseudo-class / :not() / :is() บน compound ที่ไม่ใช่ตัวสุดท้าย (เช่น .row:active .label) หรือ :has() ไหม → gStateDescendants
  • Element::setState() (เช่นกดปุ่ม → :active) mark เฉพาะ element นั้น และ mark subtree/พี่น้องถัดไปก็ต่อเมื่อ flag ข้างบนบอกว่ามี selector ที่ขึ้นกับมัน
  • inheritedDiffers เทียบ custom property (--x) ด้วยค่า ไม่ใช่ pointer (เดิมเทียบ pointer ทำให้ถือว่าเปลี่ยนทุกครั้ง ลูกทั้งหมดถูก restyle)

ผลบน Calculator: กดปุ่มหนึ่งครั้งจาก restyle 59–73 element ใช้ 49–74 ms เหลือ 4 element ใช้ 4 ms

ผลของ StyleDiff ที่ได้จากการเทียบ style เก่า/ใหม่: SD_PAINT (วาดใหม่), SD_LAYOUT (layout ใหม่), SD_STACKING (สร้าง display list ใหม่), SD_TEXT

Layout แบบบางส่วน (relayout boundary)

เมื่อ element หนึ่งต้อง layout ใหม่ engine หา boundary ที่ใกล้ที่สุด แล้ว layout เฉพาะกล่องนั้น ถ้าขนาดภายนอก (w, h, baseline, margin, scroll size, ตำแหน่ง relative) ออกมาเท่าเดิม ก็จบแค่นั้น ถ้าไม่เท่า ขยับขึ้นไป boundary ชั้นถัดไป จนถึง <html> (layout ทั้งหน้า)

Boundaryเงื่อนไข
Block ใน blockblock-level ใน flow ภายใน block/list-item/flow-root/inline-block/table-cell และความกว้างของตัวเองกับบรรพบุรุษทุกชั้นมาจาก containing block (ไม่ใช่ shrink-to-fit)
Flex item ขนาดตายตัว (fixedFlexItem)ไม่ grow, flex-basis: auto, main size เป็น px ที่ได้ตามที่กำหนดจริง (ไม่ถูก shrink), cross size เป็น px หรือ stretch ใน container แบบ nowrap

ถ้ามีกล่อง absolute ที่อ้างถึงสิ่งที่อยู่นอก boundary จะถอยไป layout ทั้งหน้า

ผลบน Calculator (flex/grid เกือบทั้งหน้า): layout ต่อการกดจาก 24–39 ms เหลือ 2 ms เพราะช่องแสดงผลเป็น flex item ขนาดตายตัว

ใน stats: layout X ms [full] หรือ [part] และตรวจความถูกต้องใน simulator ด้วย RT_CHECK_LAYOUT=1 หรือคำสั่ง layoutcheck (เทียบผล partial กับ full)

การวาด

  • วาดทีละ band (แถบแนวนอนใน SRAM) ตามลำดับ stacking context: background, border, เนื้อหา, ลูกที่ position, z-index
  • รองรับ: สีพร้อม alpha, border-radius ทุกมุม, border style ทุกแบบ, linear/radial gradient, box-shadow (outer/inset, blur), opacity, transform 2D (translate/scale/rotate), filter (grayscale, brightness, contrast, invert, opacity, sepia, saturate, blur, drop-shadow, hue-rotate), background-image/size/repeat/position, outline
  • รูป (.img, IMG1) ถูก decode ไว้ใน RAM เป็น RGB565 + alpha; ขนาดถูกย่อตอน build ให้ไม่เกิน 2 เท่าของขนาดที่แสดงจริงใน Chromium
  • Canvas 2D: คำสั่งวาดถูกบันทึกเป็น list (path อยู่ในพิกัด canvas แล้ว) และเล่นซ้ำลงทุก band ตอนวาดหน้า CPU ไม่เขียน bitmap ของ canvas ใน PSRAM เลย clearRect() เต็มพื้นที่จะล้าง list; list ที่ยาวมากถูก flatten เป็น bitmap
  • SVG: shape ถูกแปลงเป็น path ครั้งเดียว (หน่วย viewBox) แล้ว rasterize ด้วย scanline fill แบบ anti-alias ตัวเดียวกับ canvas ไอคอนจึงคมทุกขนาด fill, stroke, stroke-width, stroke-linecap, stroke-linejoin มาได้ทั้งจาก attribute และ CSS (inherit ลง element ลูก), subpath ที่ไม่ได้ปิดด้วย Z ถูก stroke แบบเปิด (Path::openEnds; canvas ได้ผลเดียวกัน) และ miter limit เป็น 4 ตาม SVG ไอคอนทุกตัวของระบบและ แอปตาชั่ง ถูกเทียบกับ Chromium แล้ว
  • Transform: กล่อง, ข้อความ, SVG และ canvas วาดผ่าน matrix ของ element; รูป (<img>) ถูก sample ผ่าน matrix เต็ม (ย่อ/ขยาย/หมุนได้) เงาของกล่องวาดเมื่อ transform มีแค่เลื่อนกับ scale (ย่อขยายตาม) ส่วนที่หมุนหรือ skew ไม่มีเงา
  • Layer cache (layer.cpp): canvas/svg ที่วางบนพื้นทึบสีเดียวและไม่มี transform ถูก render เป็น bitmap ครั้งเดียวแล้ว copy ลงทุก band
  • ข้อความ/รูปที่ bitmap ยังไม่อยู่ใน RAM ถูกข้าม (ไม่อ่าน flash ระหว่างวาด)

Font และภาษาไทย

บอร์ดไม่ rasterize font ตอน runtime เครื่องมือ build เปิดทุกหน้าใน Chromium (Playwright) เพื่อวัดว่าใช้ family/weight/size ไหน กับตัวอักษรอะไร แล้วสร้าง atlas (FNT1) ต่อ (family, weight, size)

FamilyFallback (ตัวที่ไม่มี)ชื่อที่ alias มาที่นี่
InterNoto Sans Thaisans-serif, system-ui, -apple-system, Roboto, Helvetica, Arial, serif, Georgia, …
Noto Sans ThaiInter–
JetBrains MonoNoto Sans Thaimonospace, Menlo, Monaco, Consolas, Courier, SF Mono, …
  • ขนาด ≤ 34 px ได้ charset เต็ม (ASCII, ไทย, สัญลักษณ์ และทุกตัวในข้อความของแอป) ขนาดใหญ่กว่านั้นได้เฉพาะตัวเลข/ละติน + ตัวที่หน้าใช้จริงที่ขนาดนั้น (+ ไทยทั้งชุดถ้ามีไทย)
  • gamma ของข้อความ 0.72, ขนาดปัดเป็น 0.25 px
  • System image มี atlas ขนาดที่ UI ของระบบใช้ (คีย์บอร์ด, picker, ค่า default) แอปที่ใช้ขนาดเดียวกันไม่ต้องพก atlas เอง (system-fonts.json) รายการขนาดอยู่ใน คู่มือเขียนแอป
  • ตำแหน่งสระ/วรรณยุกต์ไทย: ตาราง FntThai (base, mark, glyph variant, dx, dy) คำนวณจาก HarfBuzz ตอน build รองรับวรรณยุกต์ซ้อนบนสระบน, สระอำ, ญ/ฐ ที่ตัดหางเมื่อมีสระล่าง
  • ตัดคำไทย: ไม่มีช่องว่างระหว่างคำ จึงใช้รายการคำ (thai.dict) ที่ build สร้างจาก segmenter ของ Chromium บนข้อความของแอป แล้วตัดแบบ longest match ข้อความที่ไม่รู้จักจะตัดระหว่าง cluster เมื่อบรรทัดล้น
  • font ใน RAM เป็นของ document: ตารางและ glyph ที่คัดลอกจาก flash ถูกปล่อยทุกครั้งที่เปิดหน้าใหม่และเมื่อเปลี่ยนแอป หน้าใหม่โหลดเฉพาะ face ที่ใช้ (≈26 KB ต่อ face) ดู หน่วยความจำ
  • build อ่าน font ของทุก element รวมที่ display: none จึงใช้ element ที่ซ่อนไว้ประกาศขนาด/ตัวอักษรที่ script จะสร้างทีหลังได้

Animation และ transition ของหน้า

  • CSS transition, @keyframes + animation, Element.animate(): ค่าที่ interpolate ถูกเขียนลง computed style โดยตรงทุกเฟรม (opacity/transform ไม่ต้อง layout)
  • เปลี่ยนหน้า: <a href> ใช้ data-transition (slide ค่าเริ่มต้น, up, down, fade, none) และ data-back / #back สำหรับย้อนกลับ slide ทำใน ISR ของจอ (ดู การแสดงผล) ใช้เวลา 320 ms

Form control และ overlay

input (text, number, password, range, checkbox, radio, date, time, color, …), textarea, select, button, progress, meter, details, dialog ทำงานเหมือน browser ส่วนที่ต้องมี UI เพิ่มใช้ overlay ภายใน (DOM ปกติที่ถูก style ด้วย internal CSS):

  • คีย์บอร์ดบนจอ: ไทย (Kedmanee), English, ตัวเลข
  • popup ของ select, date/time/color picker

ปุ่มจากคีย์บอร์ดบนจอส่ง keydown ไปที่ element ที่ focus ก่อน: handler ที่เรียก preventDefault() ยกเลิกปุ่มนั้นได้ และถ้า handler ย้าย focus (เช่น Enter = ไปช่องถัดไป) ปุ่มจะไม่ถูกใส่ลงช่องเดิม
