แกนระบบ (core)

หน่วยความจำและ storage

SRAM, PSRAM และ flash ถูกใช้ทำอะไร, กฎ "ห้ามอ่าน flash ระหว่างแสดงผล" และกลไกที่ทำให้กฎนี้เป็นจริง (ImageSource, การคัดลอก font ทีละ glyph), cache ที่มีขอบเขต, งานลดหน่วยความจำต่อหน้า (รอบแอปตาชั่ง), SRAM ภายในที่ต้องเหลือให้ radio และ storage ของ OS (SD card หรือ LittleFS) พร้อม layout ของไฟล์

กฎ: ไม่อ่าน flash ระหว่างแสดงผล

Flash และ PSRAM ใช้ bus MSPI เดียวกัน การอ่าน flash ต่อเนื่องทำให้ fill DMA ดึงภาพจาก PSRAM ไม่ทัน จอจะกระตุก (วัดได้ 1170 ครั้งใน 2 วินาที เทียบกับ 0 ครั้งเมื่ออ่าน PSRAM) ดังนั้นสิ่งที่ถูกอ่านระหว่างวาดต้องอยู่ใน RAM และการอ่าน flash อื่นๆ ต้องแบ่งเป็นช่วงสั้นๆ

กฎนี้บังคับด้วยโครงสร้าง ไม่ใช่ความระมัดระวัง: image ใน flash ไม่ถูก map เข้า address space เลย จึงไม่มี pointer ไหนชี้เข้า flash ได้ โค้ดที่ต้องการข้อมูลต้องผ่าน ImageSource::read() ที่คุมจังหวะเอง

Font ใน RAM ทีละ glyph

atlas ของ font (FNT1) เก็บ glyph ที่ rasterize ไว้แล้วสำหรับ family/weight/size หนึ่งๆ การคัดลอกทั้ง atlas เข้า RAM เคยทำให้ PSRAM หมดจนบอร์ด reboot จึงเปลี่ยนเป็น:

  1. ตาราง (header, glyph table, kerning, Thai placement) คัดลอกเข้า PSRAM ครั้งเดียวต่อ face (ensure())
  2. Bitmap ของแต่ละ glyph คัดลอกตอนที่ shapeText ผลิต glyph นั้นออกมา (touch()) เก็บเป็น pointer แบบ atomic ต่อ glyph ทั้งสอง core จึงอ่านได้โดยไม่ต้อง lock
  3. ระหว่างวาด bitmap() คืน pointer ใน RAM หรือ null (ยังไม่ได้อ่านเพราะหน่วยความจำไม่พอ) ผู้วาดข้าม glyph นั้น ไม่ไปอ่าน flash
  4. ถ้า PSRAM ว่างน้อยกว่า glyph + 256 KB (kFontReserve) จะไม่คัดลอก (ข้อความบางตัวหายดีกว่าระบบล่ม)
  5. สำเนาผูกกับ (source, offset) ใน registry FaceResident เมื่อ image ถูก unmount จะถูกทำเครื่องหมาย (fontsDropSource) และคืนหน่วยความจำเมื่อไม่มีใครใช้แล้ว (fontsCollectResident)
  6. font เป็นของ document: ทุกครั้งที่เปิดหน้าใหม่ (Engine::open) FontManager::releaseResident() ปล่อยตารางและ glyph ทุก face ที่อ่านมาจาก flash แล้ว collect ทันที และ FontManager::clear() ตอนเปลี่ยนแอปก็ทำแบบเดียวกัน หน้าใหม่โหลดเฉพาะ face ที่ตัวเองวาดกลับมาจาก flash เมื่อใช้

ก่อนข้อ 6 สำเนาของ atlas ระบบไม่เคยถูกปล่อยและสะสมข้ามแอป (font ใน RAM เคยวัดได้ 105–456 KB แล้วแต่หน้า) ตัวเลขปัจจุบันอยู่ใน stats fonts-in-ram

Cache ที่มีขอบเขต

Shadow mask cache

box-shadow ที่ blur สร้าง mask (profile + มุม 4 มุม) เป็น block เดียวจาก gAllocBulk และ cache ไว้ต่อ thread วาด (สอง core จึงไม่ต้อง lock)

  • จำกัด 96 KB ต่อ thread แบบ LRU (ใช้ล่าสุดไว้ท้าย ลบจากหัว)
  • ค่า alpha ถูก quantize เป็นขั้นละ 4/255 ทำให้ shadow ที่ fade (alpha เปลี่ยนทุกเฟรม) ใช้ mask ซ้ำได้
  • ก่อนแก้: แถบล่างของ OS ที่ fade เข้าออกสร้าง mask ใหม่ทุกเฟรม ใช้แถบครั้งหนึ่งเสีย ~100 KB สะสมได้ ~800 KB จน PSRAM เหลือ 14 KB หลังแก้หน่วยความจำคงที่ไม่ว่าใช้กี่ครั้ง
  • ถ้าจอง mask ไม่ได้ (PSRAM หมด) shadow นั้นไม่ถูกวาดและ log บอก 3 ครั้งแรก แทนการ crash

JS realm ที่ยังถูกอ้างถึง

หน้าใหม่ได้ JS context ใหม่ แต่ context เก่าจะยังอยู่ถ้า background process แบบ APP ถือ closure ของมันไว้ (ประมาณ 400 KB ต่อ realm ในกรณี Calculator) ดู JavaScript runtime และ ข้อจำกัด

ลดหน่วยความจำต่อหน้า (รอบ แอปตาชั่ง)

แอปตาชั่ง รุ่นแรกทำให้ PSRAM เหลือ 15 KB บนหน้าแรกแล้ว crash วัดบนบอร์ดได้ว่าหน้าหนึ่งกิน: CSS ≈600 KB (จาก CSS 34 KB), JS context ≈690 KB, script ของแอป ≈440 KB, การวาดครั้งแรก ≈450 KB (font ≈290 KB) การแก้ทั้งหมดให้ภาพเหมือนเดิมทุก pixel (เทียบภาพใน sim) และผ่าน ASAN

SRAM ภายในและ radio

WiFi, Bluetooth และ stack ของ task ต้องใช้ SRAM ภายใน ส่วน engine จองหน่วยความจำเล็กๆ จำนวนมาก ถ้าปล่อยให้ malloc() เลือก SRAM สำหรับ block เล็ก (ค่าเริ่มต้นของ ESP-IDF) engine จะกิน SRAM จน radio เปิดไม่ได้ จึงตั้ง:

  • CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=0: malloc() เลือก PSRAM ก่อนทุกขนาด ผู้ที่ต้องการ internal ขอด้วย capability (MALLOC_CAP_INTERNAL) เอง
  • CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC=y: buffer ของ TLS (~40 KB ต่อ connection) ใน PSRAM ก่อนหน้านี้ HTTPS ล้มด้วย mbedtls_ssl_setup -0x7F00 (หน่วยความจำไม่พอ) เมื่อเปิด radio
  • stack ของ task http (10 KB) จองใน PSRAM (xTaskCreatePinnedToCoreWithCaps)
  • WiFi TX buffer แบบ dynamic, NimBLE host จาก PSRAM, data cache 32 KB, bounce buffer 12 แถว, UART RX ของ dev link 6 KB, task probe สร้างเมื่อใช้ครั้งแรก

radio ตรวจ SRAM ว่างก่อนเปิด (WiFi 34 KB, BLE 30 KB) และปฏิเสธพร้อมข้อความถ้าไม่พอ เมื่อเปิดทั้งสองแล้ว SRAM ยังว่าง ≈48 KB ดู Wi-Fi และ Bluetooth

Flash slot ของ image

ดูหลักการใน iotdash OS สรุป:

  • System image → partition sys (2.25 MB), app image → slots (3 × 1.5 MB)
  • header 4 KB ISL1 + key + hash ทำให้รู้ว่า slot มี image ไหนอยู่ ไม่ต้องคัดลอกซ้ำ
  • คัดลอกทีละ 64 KB ต่อ step() (erase + write) อ่านจาก storage ทีละ 4 KB พัก 150 µs
  • image ที่ใหญ่เกิน slot จะ error "image of N KB does not fit its M KB flash slot"
