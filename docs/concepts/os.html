iotdash OS

ชั้น OS ที่วางอยู่บน rendering engine ทำหน้าที่ boot ระบบจาก storage, แสดง home screen, เปิดปิดแอปทีละตัว, จัดการ navigation stack, แสดง system UI (แถบล่าง, dialog, overlay ตอนเปิดแอป), registry, Wi-Fi/Bluetooth และ factory reset โค้ดหลักอยู่ที่ lib/rt/os.h, lib/rt/os.cpp, lib/rt/os_net.cpp ส่วนหน้าจอระบบอยู่ใน os/core/

Reload ระบบโดยไม่ reboot

หลัง os deploy เครื่องมือจะส่ง dev-link frame OS_RELOAD ให้บอร์ดเรียก Os::reloadSystem(): flush memory.json, ปิด JS session, unmount app/ และ system/ แล้วเริ่ม boot ใหม่จาก boot image (ไม่ต้อง reset บอร์ด) เนื่องจาก hash เปลี่ยน image ใหม่จะถูกคัดลอกลง sys

System image และ app image ใน flash

ไม่มีการอ่าน image จากการ์ดตรงๆ ตอนแสดงผล ทุก image จะถูกคัดลอกลง partition ใน flash ก่อน แล้วอ่านผ่าน driver ตามต้องการ (ดูเหตุผลใน หน่วยความจำและ storage)

ImagePartitionขนาดการเลือก slot
System (os.idb)sys (subtype 0x40)2.25 MB (0x240000)slot เดียว
แอป (app.idb)slots (subtype 0x41)3 slot × 1.5 MBslot ที่มี image นี้อยู่แล้ว → slot ที่เคยเป็นของแอปนี้ → slot ว่าง → slot ที่เก่าที่สุด (ตาม stamp)

แต่ละ slot มี header 4 KB ("ISL1", size, stamp, key, hash) ถ้า key และ hash ตรงกับที่ขอ จะใช้ได้ทันทีโดยไม่คัดลอก (เปิดแอปเดิมซ้ำเร็วมาก) ตอนคัดลอกจะลบ header ก่อนเป็นอย่างแรก และเขียน header เป็นอย่างสุดท้าย ดังนั้นการคัดลอกที่ถูกตัดกลางคัน (ไฟดับ, reset) จะไม่ถูกนับเป็น image ที่สมบูรณ์ รายละเอียด format อยู่ใน Format ไฟล์

การอ่านจาก storage ตอนคัดลอกทำทีละ 4 KB และพัก 150 µs ระหว่างแต่ละครั้ง เพราะ flash file system ใช้ bus เดียวกับที่ panel ใช้เติม bounce buffer ถ้าอ่านรวดเดียว 64 KB จอจะ glitch

วงจรชีวิตของแอป

Launch

  1. Home เรียก os.launch(id) → Os::launch() (ปฏิเสธถ้าระบบยังไม่ RUNNING หรือมีแอปอื่นกำลังเปิดอยู่)
  2. System app: ใส่งานลง deferred_ (ไม่ทำในระหว่างที่ script กำลังรัน) ให้ปล่อย app image เดิม, unmount app/ แล้ว enter(app, TR_SLIDE_UP)
  3. แอปที่ติดตั้ง: เริ่ม loadImage("app:<id>", app.idb, hash) แล้วแสดง launch overlay (class launching) ที่มีชื่อแอปและ progress bar ซึ่ง tick() ปรับความกว้างตาม step()
  4. เมื่อโหลดครบ: ปล่อย image เดิม, mount ที่ app/ แล้ว enter() ถ้าล้มเหลวจะแสดง dialog "Cannot open the app: …" หรือ "The app image is damaged; install it again."

enter(app, transition)

  1. ถ้ามี dialog ค้างอยู่ จะตอบ cancel ให้ก่อน (ให้ confirm() ของ JS resolve ในขณะที่ runtime ยังอยู่)
  2. flush() memory.json ของแอปเดิม
  3. js_.endSession(): script, timer และ background process ของแอปเดิมจบทั้งหมด
  4. ตั้งแอปใหม่เป็นแอปปัจจุบัน, ล้าง navigation stack, โหลด memory.json ของแอปใหม่, สร้างโฟลเดอร์ data/
  5. เปิด <root>main.html ด้วย transition ที่กำหนด

memory.json (localStorage)

  • localStorage ของทุกหน้าในแอปหนึ่งตัวคือ map เดียวกัน เก็บในไฟล์ <app.dir>/memory.json (system app และ home ใช้ /system/memory.json)
  • โหลดตอน enter(); การเขียนจะรวมกันแล้ว flush หลัง 500 ms (memFlushAt_) และ flush ทันทีเมื่อออกจากแอป, ก่อน format, หรือเมื่อ Os ถูกทำลาย
  • การ setItem ค่าเดิมซ้ำไม่ทำให้ไฟล์ถูกเขียน
  • ไม่มีขีดจำกัดขนาดที่บังคับ แต่ไฟล์ทั้งไฟล์ถูกเขียนใหม่ทุกครั้ง ควรเก็บแค่สถานะเล็กๆ ข้อมูลใหญ่ให้ใช้ fs ใน data/

ไฟล์ของแอปและ sandbox

  • แอปเข้าถึงได้เฉพาะโฟลเดอร์ data/ ของตัวเองผ่าน open() และ fs.* path ถูก normalize (ตัด . และช่องว่าง) ถ้า .. พาออกนอก data/ จะ error "path outside the app"
  • ไฟล์ใน image ของแอป (เช่น data.json ที่ build รวมไว้) อ่านได้ด้วย fetch() แบบ relative URL
  • รูปบน storage อ่านได้เฉพาะ URL แบบ sd:/…/*.img (ใช้สำหรับ icon) และห้ามมี ..
  • Registry อ่านได้ทุกแอป (ยกเว้น key secure.*) แต่เขียนได้เฉพาะ privileged
  • ไฟล์ใต้ system/private/ ใน system image (เช่น secrets.json) เปิดเป็นหน้าไม่ได้และ fetch() ได้ 404 มีแต่โค้ด native ของ OS ที่อ่าน

Storage: SD card หรือ flash ภายใน

DevicePlatform::sdMount() ลอง mount SD card ก่อน (ที่ /sd) ถ้าไม่ได้ หรือ Preferences key storage = flash จะใช้ LittleFS บน partition fs (5.2 MB) ที่ /flash แทน ด้วย layout เดียวกันทุกอย่าง ส่วนที่เหลือของ OS ไม่รู้ว่าใช้ตัวไหน (เห็นแค่ sdRoot())

  • เปลี่ยนโหมดด้วยคำสั่ง text storage flash หรือ storage auto (มีผลตอน boot ครั้งถัดไป)
  • Settings แสดงชนิด storage (sdInfo().type เป็น FLASH เมื่อใช้ flash ภายใน)
  • ช่อง SD ของบอร์ดตัวที่ใช้ทดสอบเสียที่ฮาร์ดแวร์ ตอนนี้ระบบจึงทำงานบน flash ภายใน (ดู ฮาร์ดแวร์)

Factory reset (Format)

ปุ่ม Format ในแท็บ SD card ของ Settings (หรือบน boot screen) เรียก os.sd.format() → Os::sdFormat():

  1. ตรวจสิทธิ์, flush memory.json แล้วตัด path ทิ้ง (จะไม่มีอะไรของการ์ดเดิมถูกเขียนกลับ)
  2. Platform::sdFormat(): format SD เป็น FAT หรือ LittleFS.format()
  3. สร้าง /applications และ /system/data
  4. เขียน system ที่กำลังรันกลับลงไป: stream os.idb จาก flash slot ทีละ 4 KB, เขียน os.json (version + hash) และ /system/assets/default-icon.img ระบบจึง boot ได้อีกครั้งโดยไม่ต้อง deploy ใหม่
  5. ล้าง memory ในหน่วยความจำและ regClear() (ค่าตั้งกลับเป็นค่าเริ่มต้น)

ผลคือเหลือแค่ file system กับ system: แอปทั้งหมดและข้อมูลของแอปหายไป จากนั้นติดตั้งแอปใหม่ได้จากแอป Apps (store) หรือ iotdash run --device ในโฟลเดอร์ของแอป

ติดตั้ง/ลบแอปจากคอมพิวเตอร์ขณะเครื่องทำงาน

iotdash install และ iotdash uninstall (--to device) เขียนไฟล์ผ่าน dev link (FS_WRITE, FS_DELETE, …) แล้วส่ง APPS_CHANGED พร้อม id ของแอป บอร์ดเรียก Os::appsChanged(id):

  • ถ้าแอปที่เปลี่ยนคือแอปที่กำลังรัน → ปิดแอปกลับ home (image ถูกเปลี่ยนจากข้างใต้)
  • ไม่เช่นนั้น → ส่ง event apps ให้ home ซึ่งฟังด้วย os.on('apps', render) แล้ววาดรายการแอปใหม่ทันที

แอป Apps และ iotstore

system app Apps (os/core/apps/store/) คุยกับ API ของ store (store/docs/API.md) ที่อยู่ของ store เก็บใน registry store.url (ตั้งจากปุ่ม Store address ในแอป)

  • Store: GET /api/store/apps?os=<os.version> ได้แอปที่มีเวอร์ชัน published ซึ่ง os_min ไม่ใหม่กว่า OS นี้ เทียบกับ os.apps(): ยังไม่มี → Install, เวอร์ชันใน store ใหม่กว่า → Update, ไม่เช่นนั้น → Open แตะแถวเพื่อดูทุกเวอร์ชัน (วันที่, ขนาด, OS ขั้นต่ำ, release notes) และติดตั้งเวอร์ชันใดก็ได้ (Update / Go back / Reinstall)
  • ปุ่ม ⋮ ข้าง Open ของแต่ละแอป: เมนู Kiosk mode (ด้านล่าง)
  • Installed: แอปบนการ์ดพร้อมป้ายที่มา Store / USB / Card จาก install.json (format), เวอร์ชัน, Update ถ้ามีใหม่กว่า, "Use store's" สำหรับแอปที่ลงผ่าน USB แต่มีใน store, Remove
  • ติดตั้ง: POST /api/store/apps/<id>/install ได้ URL ของแพ็กเกจ (presigned) แล้ว os.store.install(): Platform::download ส่ง body ทีละชิ้นให้ IdbzWriter (lib/rt/os_store.cpp) บน thread ของ http เขียนแต่ละไฟล์ลง /applications/.store-<id>/ พร้อม SHA-256; จบแล้วบน thread ของ engine ย้ายไฟล์แทนของเดิม (app.idb สุดท้าย), เขียน install.json, appsChanged(id) ล้มที่จุดใดก็ตาม ไฟล์เดิมของแอปไม่ถูกแตะ
  • ความคืบหน้า: event install ทุก ~150 ms; ติดตั้งแอปที่กำลังเปิดอยู่ไม่ได้
  • รายการล่าสุดและไอคอน (IMG1 จาก store) เก็บที่ /system/data/store/ ใช้แสดงตอน offline

บนบอร์ดจริง (flash ภายใน, Wi-Fi, backend ในเครื่อง Mac): แอปขนาด 481 KB อัปเดต 1.0 → 1.1 ใน 5.3 วินาที

Kiosk mode

ให้แอปที่ติดตั้งไว้ตัวหนึ่งเป็นหน้าจอเดียวของบอร์ด (เช่นเครื่องชั่งหน้าร้าน) ตั้งจากแอป Apps: ปุ่ม ⋮ ข้าง Open → Kiosk mode → ใส่รหัสผ่านสองครั้ง → Start (os.kiosk.start(id, password), lib/rt/os_kiosk.cpp)

  • แอปเปิดทันที และเปิดเองทุกครั้งที่ระบบเริ่ม (ต่อจาก home screen ที่ใช้เป็นฉากหลัง)
  • ทุกทางออกจากแอป: ปุ่ม Home ของแถบระบบ, Back ที่หน้าแรกของแอป, os.home() จากหน้าของแอป จะเปิด dialog ของระบบที่มีช่องรหัสผ่าน (ด้านบนจอ เหนือ keyboard) ผิด = "Wrong password" แล้วถามใหม่, Cancel = อยู่ในแอปต่อ, ถูก = ปิด kiosk mode แล้วกลับ home (เปิดใหม่ได้จาก Apps)
  • แอปถูกอัปเดตขณะเป็น kiosk: ระบบเปิดเวอร์ชันใหม่ให้เอง; แอปถูกลบ: kiosk mode ปิดเอง (ไม่มีอะไรให้ล็อก)
  • Registry secure.kiosk = {app, salt, hash} (hash = SHA-256 ของ salt + รหัสผ่าน, มองเห็นเฉพาะ system) factory reset ล้างไปพร้อม registry
  • ช่องรหัสผ่านอยู่ใน system UI (internal): ตัวอักษร, focus, Enter ไม่ถึง script ของแอป (OsHooks::internalKey) และระหว่างที่ dialog เปิด touch ที่ไม่ใช่ปุ่มของ dialog ไปถึง keyboard ของ engine เท่านั้น
  • ลืมรหัสผ่าน: iotdash device kiosk-off ผ่าน USB (frame KIOSK_OFF) ปิด kiosk mode แล้วกลับ home

Home screen

  • os/core/home/: แสดงแอปหน้าละ 10 ตัว (PER_PAGE) เลื่อนซ้ายขวาด้วย scroll snap พร้อมจุดบอกหน้า และจำหน้าล่าสุดใน localStorage.homePage
  • นาฬิกาเป็น background process แบบ PAGE (หยุดเองเมื่อเปิดแอป) อ่าน clock24 จาก registry
  • เมื่อยังไม่มีแอปที่ติดตั้ง จะแสดงคำแนะนำ iotdash run --device และแอป Apps

แท็บ Connection

connection.js แสดงสิ่งที่ OS รู้และส่งคำขอผ่าน os.wifi / os.bt เท่านั้น (รายการเครือข่ายและรหัสเป็นของ OS) segment ที่เลือกถูกจำใน localStorage.connView

Segmentมีอะไร
Wi-Fiสวิตช์เปิดปิด (wifi.enabled), เครือข่ายที่ใช้อยู่พร้อมสถานะ (Connected / Connected, no internet / กำลังต่อ), IP และปุ่ม Disconnect / Forget; รายการจาก scan พร้อมแถบสัญญาณ (4 ขั้นจาก RSSI) และรูปกุญแจ เครือข่ายที่บันทึกขึ้นก่อนพร้อมปุ่ม Forget; scan ใหม่เมื่อเปิดแท็บ (ถ้าเกิน 8 วินาที) และทุก 20 วินาทีระหว่างที่แท็บแสดงอยู่
Wi-Fi: เข้าร่วมแตะเครือข่ายที่บันทึก = ต่อด้วยรหัสเดิม; เครือข่ายเปิด = ต่อทันที; เครือข่ายมีรหัส = sheet เล็กสำหรับใส่รหัส (ปุ่ม Join ใช้ได้เมื่อยาว ≥ 8 ตัว, Enter = Join, ปุ่มรูปตาแสดงรหัส, แตะนอก sheet = ยกเลิก) รหัสผิดจะเปิด sheet อีกครั้งพร้อม "Wrong password, try again"
Bluetoothสวิตช์ (bt.enabled, สถานะ "On · starts when a device is used" เมื่อ radio ยังไม่เริ่ม), My devices (อุปกรณ์ที่จำไว้, ที่ต่ออยู่ขึ้นก่อน, ปุ่ม Connect / Disconnect / Forget), Devices nearby (scan 8 วินาที, แตะเพื่อต่อแล้วถูกจำ, อุปกรณ์ไม่มีชื่อซ่อนไว้หลัง "Show N devices without a name")

Forget ทั้งสองแบบถามยืนยันด้วย os.confirm ผลของการกระทำแสดงเป็น toast ด้านล่าง หน้านี้อัปเดตตาม event net และ bt ไม่ใช่ event registry โมเด็ม 4G Cat-1 ถ้ามีในอนาคตจะเพิ่มเป็นอีก segment (ยังไม่ได้ทำ) รายละเอียดของ policy อยู่ที่ Wi-Fi และ Bluetooth
